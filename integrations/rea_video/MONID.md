# Monid — пробный поиск референсов Кадра

Дата: 08.11.2026. Основание: Leo разрешил подключить Monid и попробовать поиск на стартовом долларе, без пополнения; ранее запросил также TikTok и Facebook.

## Подключение
Официальный Streamable HTTP MCP: `https://mcp.monid.ai/v1`.
В этой среде добавлен через `codex mcp add monid --url https://mcp.monid.ai/v1`, OAuth завершён. Это локальная конфигурация Codex, а не развёртывание на всех исполнителях. API-ключи и OAuth-токены не сохранять в репозитории/артефактах/сообщениях. Если текущий клиент не видит новый MCP, загрузить подключение в свежем клиенте, а не читать хранилище токенов.

Официальные источники: [MCP setup](https://monid.ai/docs/guide/quickstart-mcp), [Monid workflow](https://monid.ai/SKILL.md), [promo credit](https://monid.ai/docs/api-reference/wallet/redeem-a-promo-code).

## Разрешённый пробный объём
- Только подтверждённый `MONID-SIGNUP` / `signup_credit`, максимум $1 суммарно. Проверять реальный баланс и удержания, не считать рекламное обещание начислением.
- Для первого теста исполнитель установил меньший предел: $0.10, по одному поисковому запуску на площадку. Это не постоянный новый бюджет и не разрешение потратить весь доллар немедленно.
- Пополнение, checkout, карта, автопополнение, подписки, генерация медиа и периодические платные ресурсы не разрешены. При исчерпании промокредита остановиться. Treg или другие кошельки автоматически не использовать.
- Для нового платного бюджета вне стартового кредита требуется отдельное решение Leo. Фоновый мониторинг не включён.

## Поиск
**Ограничение первого теста:** у Facebook AnyAPI `/facebook.search_posts` фактическое списание $0.02923 оказалось выше расчёта $0.01627 при `limit:5`. Выставлено девять единиц при пяти возвращённых записях. До выяснения этого расхождения endpoint не использовать повторно; не считать указанный `maxCost` доказанным финансовым ограничителем. Остальные два источника в этой пробе списали ожидаемую фиксированную цену. Это наблюдение одного теста, а не гарантия будущих цен.

1. Проверить workspace, баланс, промокредит и уже запущенные задачи. При временном provisioning завершить настройку кабинета, затем перепроверить; не создавать дубликаты аккаунтов/ключей.
2. Через Monid discover найти соответствующую задачу, inspect прочитать фактическую схему и цену. Не копировать параметры между одноимёнными провайдерами Treg и Monid: их пути/обёртки различаются.
3. Instagram: поиск Reels по ключевым словам либо публичным хештегам/аккаунтам; TikTok: keyword video search. Facebook: различать общий поиск публичных постов и поиск видео/Reels. Текстовый пост не считать видеореференсом.
4. До run посчитать максимальную цену. Для per-result задавать документированный предел, учитывать фиксированную часть. Для фиксированного per-call допустима страница 12/20 результатов: до пяти сохраняемых кандидатов — лимит отчёта, а не обязательный параметр API. Перепроверять схему и цену перед новыми запусками.
5. Записать ID запуска до ожидания результата. При тайм-ауте проверять тот же ID, не отправлять оплачиваемый run повторно. В первом тесте без пагинации и платных fallback.
6. В отчёте фиксировать дату, платформу, запрос, endpoint, run ID, статус, фактическую стоимость, прямые ссылки, автора и основания соответствия теме. Неизвестные метрики не выдумывать; не приравнивать Facebook+Instagram plays к Instagram-only просмотрам.
7. Далее действует профиль Кадра: отбор → реальное видео → просмотр/review → карточка/индекс. Поисковая выдача не READY. `kadr.py` сейчас принимает Instagram URL или локальный файл; TikTok/Facebook передавать ему только после законного получения доступного локального MP4, без cookies/логинов в загрузчике. Доступность поиска не доказывает скачивание/просмотр/разбор этих видео.

Проверка пилота и реальные ограничения фиксируются в `VALIDATION.md`. Полные машинные результаты и медиа остаются вне Git, в локальной папке задания. Секретов и персональных данных аккаунта в отчёте не должно быть.
