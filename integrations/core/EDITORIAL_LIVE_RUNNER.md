# Simba CORE: реальный исполнитель редакционной цепочки (opt-in)

**Область:** только текстовые редакционные роли Simba → Critic → Simba → Humanizer. Киностудия, Rafael, рендеринг, публикация, отправка клиенту и изменение ранее утвержденных текстов здесь отсутствуют.

## Что реализовано

Файл integrations/core/editorial_live_runner.py при **явно разрешенном оплачиваемом запуске** вызывает официальный OpenAI Responses API по фиксированному HTTPS-адресу. Каждый этап — отдельный API-вызов с собственными правилами. Перед вызовами загружается канонический общий CORE KB preflight (карта, runtime, бренд, аудитория, индекс, pipeline, learning) и правила трех ролей. Чтение KB **не заменяет** отдельную проверку текущих фактов, работу Router, подбор TIA или утверждение Лео.

1. Simba пишет одну тестовую редакцию по новому брифу.
2. Critic проверяет точную редакцию и возвращает структурированные PASS/REVISE, оценку и замечания. PASS только от 8/10 и без блокеров.
3. При REVISE Simba вызывается вновь; исправление перепроверяется. Три подряд безрезультатных исправления останавливают цепочку.
4. При PASS вызывается Simba finalize. Любое изменение текста требует нового PASS Critic для новых байтов.
5. Humanizer вызывается отдельно. Если результат изменен, финальную редакцию снова проверяет Critic; REVISE блокирует готовность.
6. В приватный отчет сохраняются идентификаторы ответов провайдера, роли, шаги, timestamp, модель и SHA-256 точного входа, выхода и загруженных правил.

Идентификаторы HTTP-ответов **не являются криптографическими удостоверениями** или разрешениями на публикацию. Фактчек внешних источников остается отдельным этапом. Выбор Лео, одобрение текста, архивация и публикация в данном runner не выполняются.

## Запуск без расходов

Создать локальный UTF-8 файл с новым безопасным брифом без клиентских данных. Не изменять существующие APPROVED-архивы.

    python integrations/core/editorial_live_runner.py --brief-file /private/brief.txt --output-dir /private/simba-audit

Статус без флагов live — BLOCKED_LIVE_EXECUTOR_NOT_RUN. Никаких платных вызовов нет.

## Отдельно разрешенный live-пилот

Только при наличии в изолированном runtime переменной OPENAI_API_KEY, отдельно утвержденного бюджета и заранее проверенной цены модели:

    python integrations/core/editorial_live_runner.py --brief-file /private/brief.txt --output-dir /private/simba-audit --model MODEL_ID --max-calls 12 --max-output-tokens 2400 --execute-live --permit-billable-api-calls

Max calls ограничивает **число API-запросов**, а не стоимость. Автоповторов при неизвестном исходе сети нет. Офлайн-CI не имеет API-ключа и запускает только unit-тесты. API-ключи никогда не журналируются.

Отчет JSON и финальный TXT сохраняются только **за пределами публичного репозитория** с файловыми правами 0700/0600. Не загружать приватный текст, клиентские данные и закрытые ссылки в публичные Issues/PR.

## Семантика статусов

- BLOCKED_LIVE_EXECUTOR_NOT_RUN: только preflight.
- BLOCKED_RUNTIME_INTEGRATION: ключ, модель, KB или окружение недоступны.
- BLOCKED_EDITORIAL: редакционная цепочка заблокирована; частичный журнал сохранен.
- DECLARED_TEST_ONLY: подставной транспорт unit-тестов, никогда не production PASS.
- LIVE_EDITORIAL_PILOT_UNVERIFIED: клиент OpenAI выполнил отдельные API-вызовы в приватном пилоте. Это **не** TEXT_READY_FOR_LEO: внешнее подтверждение фактов, source resolution, TIA, подлинность receipts и выполнение в ChatGPT runtime пока не установлены.

## Независимая офлайн-проверка сохраненных артефактов

После явно разрешенного пилота отчет и точный TXT можно проверять без API и без расходов:

    python integrations/core/editorial_receipts_audit.py --report /private/simba-audit/simba-core-RUN_ID.json --text /private/simba-audit/simba-core-RUN_ID.txt

Проверяются порядок отдельных шагов, точное совпадение SHA-256, смена редакций, PASS/REVISE и уникальность указанных request/response IDs. Статус **DECLARED_RECEIPTS_CONSISTENT_AUTHENTICITY_UNVERIFIED** означает только непротиворечивость записанных JSON/TXT. Он **не удостоверяет** действительность вызовов у провайдера: JSON можно подделать, offline tool не получает подтверждение от OpenAI. Не переводить этот статус автоматически в APPROVED_TEXT, TEXT_READY_FOR_LEO или PUBLISHED.

**Остается:** оплаченный live-пилот не проводился, подключение к runtime ChatGPT и независимая аутентификация внешних receipts не подтверждены. ISSUE #220 сохраняет открытые задачи. Зеленый CI не доказывает их выполнение.
