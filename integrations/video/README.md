# Video: утверждённый пост → вертикальный ролик до 60 секунд

Рендерер фото-историй Simba. Берёт **утверждённый пост** из Content Library, **кадры Рафаэля** и **реплики Сценариста**
и собирает ролик 1080×1920 (Reels / Shorts / TikTok / Facebook): движение камеры по кадрам, утвержденный голос Simba WarmBaritone (Google Gemini Voice Design),
субтитры с подсветкой произносимого слова, карточка оффера, финальная карточка с постером и контактом, музыка и звуки.

Процесс, роли и gates описаны в `SIMBA KNOWLEDGE BASE/06_AGENT_WORKFLOWS/VIDEO_PIPELINE.md`. Этот файл — только про инструмент.

Решение Leo от 06.11.2026: исполнитель видео не проверяет актуальность или достоверность
цен, наличия и других фактов. Инструмент по-прежнему технически сверяет числа с исходным
текстом; это контроль переноса, не проверка текущих условий предложения.

## Установка (один раз, на машине Leo)

Нужны Node 20+, Python 3.11–3.13 и ffmpeg (`winget install Gyan.FFmpeg`; путь WinGet инструмент находит сам).

```powershell
cd integrations\video
npm install
node node_modules\playwright-core\cli.js install chromium-headless-shell

```

## Задание: папка с `video-spec.json` и картинками

Папка задания живёт вне Git (по умолчанию `integrations/video/jobs/<packageId>/`, каталог в `.gitignore`).
В ней лежат кадры Рафаэля (9:16, без текста), финальный постер 1:1 и `video-spec.json`:

| Поле | Что это |
|---|---|
| `packageId` | id ролика (латиница, цифры, `.-_`), из него имя файла |
| `sourcePost` | путь к `*__APPROVED.md` от корня репозитория; файл обязан иметь `STATUS: APPROVED` и раздел `## APPROVED_TEXT` |
| `voice` | `{"provider": "simba"}` (по умолчанию, выбранный постоянный Google Gemini WarmBaritone); Edge TTS только при явном `{"provider": "edge", "name": "ru-RU-DmitryNeural", "rate": "-4%"}` |
| `scenes[]` | 1–8 сцен: `image`, `move` (`push` / `pull` / `pan-left` / `pan-right` / `rise`), необязательный `title`, `focus` `[x, y]` 0–1, `lines[]` |
| `offer` | карточка оффера: `title`, `rows[]`, `price`, `note`, `lines[]`, необязательный `bg` (картинка фона) |
| `end` | финал: `poster`, `cta`, `contact`, `brand`, `lines[]` |
| `lines[]` | `{"text": ...}` — субтитр и то, что сверяется; `say` — что произносит голос (числа словами, латиница кириллицей); `asr` — как Whisper должен это услышать, если отличается от `text` |

Пример: [`examples/costa-diadema-fjords.video-spec.json`](examples/costa-diadema-fjords.video-spec.json).

### Сцены из готовых видеоклипов (Grok и др.)

Вместо `image` сцена может взять `clip` (`.mp4` / `.mov` / `.m4v` / `.webm`) из папки задания:

```json
{ "clip": "c1.mp4", "lines": [{ "text": "Корабль красивый." }, { "text": "А гулять-то когда?" }] }
```

- Клип кадрируется под размер ролика (cover), длина сцены = длина клипа; `in` / `out` (секунды) обрезают его.
  Камера по умолчанию неподвижна (`move: "none"`): клип уже анимирован.
- **Голос берётся из самого клипа** (только при явном `"voice": "clip"`): губы совпадают с речью. Whisper проверяет, что клип
  произносит строки сцены (сходство ≥ 0.90 — обрезанная фраза не пройдёт), и даёт тайминги для субтитров.
  `"voice": "tts"` (новое значение по умолчанию) — речь из исходного клипа не берется, строки озвучивает утвержденный Simba WarmBaritone. `"voice": "clip"` задается явно, если речь должна звучать из исходного клипа.
- Если у клип-сцены нет `lines`, субтитры берутся из распознанной речи и помечаются в `qa-report.md` для проверки Leo;
  fact gate проверяет и их.
- Музыка — одна общая **синтезированная** дорожка на весь ролик (`"music": {"style": "lounge", "bpm": 100}` или спокойная по умолчанию),
  уходит под голос клипов. Своя музыка клипа остаётся в их звуке, поэтому в Grok её лучше просить тихой или без неё.
- `end.bg` / `offer.bg` можно указать именем клипа — фоном станет его последний кадр.

Тест без Grok: `examples/make_test_clips.py` делает «клипы» из картинок с голосом и пометкой «ТЕСТОВЫЙ КЛИП».

### Нарисованные сцены (`"insert"`)

Сцена без картинки и клипа, нарисованная кодом (`template/inserts.js`, `template/cartoon.js`):

- `{"type": "route", "title", "path": [[lon, lat, "Порт"?], …], "ports": {…}, "rows": […]}` — карта маршрута:
  золотой пунктир по точкам, порты загораются, ниже дни и часы стоянок (данные — из поста, их видит fact gate);
- `{"type": "cartoon", "set": "deck|deck2|pool|map|cafe|promenade|halong|halong2|angkor|street|rice|airport", "act"?}` —
  мультяшный Симба с движением пасти в такт голосу; `airport` принимает `"stops": [{"name", "date"?}]` для табло.
  **Только по явной команде Leo** (VISUAL_RULES не допускает мультяшного маскота по умолчанию).

Вставка может иметь `lines` — тогда её длительность считается по голосу, как у картинки.
Финальная карточка принимает `end.table`: `{"title", "sub", "rows": [["Каюта", "1492$"], …], "note"}`.

### Motion Lab — переходы между сценами

Каталог и подготовка переходов: [Motion Lab](https://headless-cvcdjldqjlx-leostraveltips-140e.wix-site-host.com).
Выберите эффекты и длительность, загрузите **существующий** `video-spec.json` из папки задания,
проверьте назначение на каждой границе и скачайте обновленный `video-spec.json`.
Сайт работает локально в браузере: содержимое задания не отправляется в Wix.
План переходов JSON является справочным, **рендерер принимает измененный video-spec.json**.

У второй и последующих сцен может быть поле `transition` — способ входа из предыдущей сцены:

```json
{
  "image": "s2.png",
  "move": "pan-left",
  "transition": {"id": "portal", "duration_ms": 900},
  "lines": [{"text": "Следующая остановка — Прага."}]
}
```

- Поддерживаются 30 ID из `template/transitions.js`; `duration_ms` — целое от 400 до 2400.
- Без `transition` старый монтаж с `crossfade=0.6` секунды сохраняется без изменений.
- `renderer: "simba"` и `renderer: "hyperframes"` используют одну реализацию
  через `template/film.js`. Это постадийный выбор, не другой голос или другой сценарий.
- Для сложных художественных переходов используется стилизованная Canvas2D-имитация;
  3D, optical flow, точная семантическая маска объекта или настоящая географическая карта
  не генерируются автоматически. На живых MP4-клипах проверяйте артефакты на границах.
- Выбор на сайте **не запускает** A2E, TTS, платный рендер, не меняет утвержденную музыку и
  не разрешает публикацию. После передачи спецификации действуют обычные gates,
  итоговый Video QA и отдельное утверждение Leo.

### Subtitle Studio — оформление и синхронизация слов

Редактор: https://headless-cvcdjldqjlx-leostraveltips-140e.wix-site-host.com/subtitles.html

В редакторе теперь можно:
1. выбрать одну из **5 анимаций слов** и один из **24 стилей**;
2. загрузить `timeline.json` созданного ролика, чтобы посмотреть **настоящие таймкоды Whisper**;
3. загрузить подходящий локальный WAV/MP3 (предпросмотр синхронно с аудио);
4. загрузить существующий `video-spec.json` и скачать **его копию** с одним полем `subtitleStyle`.
Файлы при этих операциях остаются в браузере. Сайт ничего не транскрибирует и не запускает рендер.

Пример поля в корне существующего `video-spec.json`:

```json
"subtitleStyle": {
  "style": "luxury",
  "motion": "active-pop",
  "color": "gold",
  "scale_percent": 110,
  "position": "bottom"
}
```

`style`: 24 ID из `template/subtitle_styles.js` (`clean` по умолчанию только если выбран иной недопустимый ID на уровне Canvas; строгая проверка Python отклоняет такой файл).
`motion`: `karaoke`, `active-pop`, `caption-swap`, `highlight-strip`, `word-reveal`.
`color`: `lime|gold|sky|white`; `scale_percent`: целое 80–135; `position`: `top|middle|bottom`.

**Синхронизация в MP4:** `make_video.py` по-прежнему строит `timeline.json` на настоящих Whisper `words[]`; новая Canvas2D-отрисовка использует эти абсолютные временные отметки. Рендереры `simba` и `hyperframes` выполняют одинаковые `template/film.js` и `template/subtitle_styles.js`. Никакого повторного распознавания или платного вызова от сайта нет.

Без `subtitleStyle` сохраняются старые субтитры без изменений. Данные `timeline.json` в редакторе служат **для предпросмотра**, а не как непроверенная замена таймкодов, используемых рендерером. Стили в MP4 воспроизводятся как Canvas2D-варианты веб-оформления, поэтому возможны визуальные отличия. Проверять мелкий текст и наложения на финальных кадрах, не пропускать Whisper/числовые/читабельность/громкость QA и утверждение Leo.

### Флаги

- `--plan-only` — таймлайн и проверка чтения без рендера; кадры смотреть через `node engine/render/still.mjs <job> <t> … --size 1080x1920`.
- `--draft` — источник ещё не утверждён (по команде Leo): ролик получает статус `VIDEO_DRAFT_SOURCE_NOT_APPROVED`, не для публикации.
- `--workers N` — параллельные браузеры (по умолчанию 2: на встроенной графике больше зависает).

## Запуск

```powershell
integrations\video\.venv\Scripts\python integrations\video\make_video.py integrations\video\jobs\<packageId>
```

Порядок и gates (любой провал останавливает сборку с причиной):

1. `STATUS: APPROVED` у исходного поста.
2. **Fact gate:** каждое число на экране и в субтитрах (цены, даты, телефоны, ночи) должно стоять в `APPROVED_TEXT` буквально.
3. Голос: постоянный Google Gemini WarmBaritone по каждой реплике; приватный Voice Design ID считывается из подтвержденного JSON на Drive, WAV кэшируются в `voice/.cache`. Edge TTS только по явному `voice.provider=edge`.
4. **Speech check:** Whisper слышит каждую реплику обратно (сходство символов ≥ 0.90); заодно даёт тайминги слов для субтитров.
5. Таймлайн из длительности реплик; ролик длиннее 60 с не собирается.
6. **Reading check:** каждая надпись держится на экране не меньше «символы ÷ 15 + 1,5 с».
7. Рендер кадров (headless Chromium), микс (музыка уходит под голос), мастеринг −14 LUFS, `.srt`, обложка.
8. Финальная проверка: длительность, громкость, чёрные кадры, Whisper по готовому миксу → `qa-report.md`.

Результат в папке задания: `<packageId>.mp4`, `<packageId>.srt`, `cover.jpg`, `qa-report.md`.
Статус `VIDEO_READY_FOR_LEO` не разрешает публикацию — она остаётся отдельной командой Leo.

Тестовый прогон без Рафаэля: `python examples/make_test_frames.py jobs/<packageId>` рисует кадры-заглушки с красной
пометкой «ТЕСТОВЫЙ КАДР». Такие ролики не публикуются.

## Происхождение и лицензии

- `engine/render/*.mjs`, `engine/lib.js`, `engine/sfx.py` — из [lemo-opuscar](https://github.com/lemomo-ai/lemo-opuscar), MIT (`engine/LICENSE-lemo-opuscar`).
- Шрифты Montserrat и Playfair Display — SIL OFL 1.1 (`fonts/OFL-*.txt`).
- Без `music.file` музыка и звуки синтезируются кодом (`audio.py`), как раньше. С `music.file` `make_video.py` через FFmpeg преобразует MP3/WAV/M4A/AAC/FLAC/OGG в 48 кГц stereo WAV, а `audio.py` подставляет эту запись вместо синтезированного фона и сводит с речью и звуковыми эффектами. Реальная коммерческая лицензия подтверждается Музыкальным редактором отдельно; `rights_confirmed=true` — свидетельство проверки, а не автоматическая юридическая экспертиза.
- Голос — утвержденный постоянный Google Gemini Voice Design (Simba WarmBaritone). Для коммерческого использования необходимо соблюдать условия Google. Наследуемый Edge TTS доступен только по явному запросу; условия Microsoft проверяются отдельно.

### Внешняя бесплатная музыка (реализовано в MP3/FFmpeg integration · 05.11.2026)

Положите выбранный Музыкальным редактором легально используемый аудиофайл в папку задания, например `music/prague.mp3`. Укажите `music` в `video-spec.json`:

```json
"music": {
  "file": "music/prague.mp3",
  "rights_confirmed": true,
  "start_s": 0,
  "loop": false,
  "gain_db": -8,
  "fade_in_s": 0.4,
  "fade_out_s": 0.8
}
```

- `rights_confirmed`: обязательное явное подтверждение проверки прав на коммерческое видео и нужные платформы. Не ставить `true`, пока Музыкальный редактор не проверил условия и не сохранил `music-handoff.json` с ссылками на трек/лицензию.
- `file`: локальный аудиофайл внутри задания; абсолютные пути и выход из папки задания запрещены. Скачивание с сайтов не выполняется рендерером. Поддержаны MP3, WAV, M4A, AAC, FLAC и OGG, макс. 200 MB.
- `start_s`: начало фрагмента исходного трека (секунды, ≥ 0), `loop: true` повторяет короткую композицию (с учетом возможной слышимости стыка); `loop: false` требует длину не меньше всего ролика.
- `gain_db` (−36…+6), `fade_in_s` и `fade_out_s` (0…10) регулируют подложку. Вокал/диалоги клипов и фоли сохраняются; под речью музыка автоматически приглушается. Финальные loudness/peak/Whisper QA и одобрение Leo остаются обязательными.
- Если `music.file` отсутствует, старый синтезированный soundtrack `{"music": {"style":"calm"}}` работает без изменений.
- `--plan-only` проверяет спецификацию и наличие аудиофайла, но не декодирует/не монтирует дорожку. Только полный рендер дает доказательство, что запись попала в MP4.

Проверка импорта без сети/платных сервисов из корня репозитория (нужны Python deps и FFmpeg):

```bash
python -m unittest discover -s integrations/video/tests -p "test_music_input.py" -v
```

Лицензия — неотъемлемая часть workflow Музыкального редактора. Треки не сохраняются в Git: музыка должна находиться только в папке задания `integrations/video/jobs/` (gitignored).


## Постоянный голос Simba — Gemini WarmBaritone (07.11.2026)

**Правило Leo от 07.11.2026 — резервный движок:** если основной
`gemini-3.8-flash-tts` недоступен, не отвечает, возвращает HTTP 429 или ошибку
сервиса, исполнитель автоматически переходит на `gemini-3.8-flash-lite-tts`
с тем же сохранённым голосом WarmBaritone и тем же текстом. Дополнительное
подтверждение перехода не требуется. Готовые фрагменты используются повторно;
основной движок повторно не вызывается. Если результат основного запроса
неизвестен, это фиксируется в журнале вместе с возможной оплатой обеих попыток.
На резервном движке допускается одна попытка для недостающего фрагмента;
при её сбое исполнитель сообщает причину, без бесконечного переключения.
Переход реализован в `simba_voice.py`: HTTP 429, ошибки HTTP 5xx и сетевые
сбои/тайм-ауты переключают текущую и оставшиеся недостающие реплики на Flash-Lite.
Для каждого движка ведётся отдельный журнал попыток и кэш; успешный резервный
WAV используется и при следующем запуске. Ошибки запроса и авторизации (HTTP
400/401/403) не вызывают переключение. При неопределённой старой попытке без
записанной причины сбоя сборка останавливается для разбора, без повторного вызова.

Голос утвержден пользователем и записан в `integrations/tts/prague_male_voices.json`. В новых роликах `voice.provider` по умолчанию равен `simba`. Старые поля `voice.name` и `voice.rate` без явного `provider=edge` **не включают старый голос**. Для немых анимационных клипов `scenes[].voice` по умолчанию `tts`; собственный голос клипа разрешается только через явное `"voice": "clip"`.

**Доступ к постоянному ID:** голос уже создан. Его ID остается только в приватном Google Drive, в папке `Simba Private TTS Prague 2026-11-07`, файл `SimbaDesign_WarmBaritone.json`. Рендерер ищет именно эту запись, проверяет ее метаданные и приватность и использует один и тот же ID во всех синтезах. ID и ключ **не вносятся в video-spec.json или публичный GitHub**.

В GitHub Actions, где уже настроены `GEMINI_API_KEY` и `GDRIVE_OAUTH_CLIENT_ID`, `GDRIVE_OAUTH_CLIENT_SECRET`, `GDRIVE_OAUTH_REFRESH_TOKEN`, поиск голоса автоматический. Локальный Python на Windows **не видит GitHub Secrets автоматически**. Для локального запуска администратор должен установить `GEMINI_API_KEY` в пользовательском окружении, а также **один** из способов определения голоса:

- `SIMBA_GEMINI_VOICE_METADATA_FILE` — абсолютный путь к локальной приватной копии `SimbaDesign_WarmBaritone.json`, скачанной с Google Drive; не помещать в Git.
- Или имеющиеся переменные `GDRIVE_OAUTH_CLIENT_ID`, `GDRIVE_OAUTH_CLIENT_SECRET`, `GDRIVE_OAUTH_REFRESH_TOKEN` для автоматического чтения Drive.
- Или `SIMBA_GEMINI_VOICE_ID` — секретное значение уже созданного голоса (только через менеджер секретов/переменных, не в коммитах).

Пример PowerShell для запуска на локальном ПК **после безопасной установки** необходимых секретов:

```powershell
$env:SIMBA_GEMINI_VOICE_METADATA_FILE = "C:\\Private\\SimbaDesign_WarmBaritone.json"
# GEMINI_API_KEY передан через защищенное окружение, не пишите его в консоль/историю.
integrations\video\.venv\Scripts\python integrations\video\make_video.py integrations\video\jobs\<packageId>
```

**Платная генерация:** для каждого текста допускается одна попытка основного движка и, при его недоступности, одна попытка Flash-Lite по правилу выше. Перед каждым вызовом создаётся отдельный `voice/.cache/<sha>.attempt.json`, включающий модель; сетевые ошибки и возможная оплата фиксируются без секретов. Основной запрос после сбоя не повторяется. Неудачная попытка резервного движка блокирует дальнейшие запросы этой реплики до разбора. Успешный WAV любой из двух моделей повторно используется из кэша. Лимиты на один рендер: не более 16 новых реплик и 1200 новых символов (по умолчанию). Ключ недоступен или нет утверждённого ID — сборка останавливается. `--plan-only` также синтезирует отсутствующую речь и может расходовать квоту; для проверки без расходов используйте офлайн-тесты.

Проверка интеграции **без сетевых вызовов и списаний**:

```powershell
python -m unittest discover -s integrations/video/tests -p test_simba_voice.py -v
```

Полный MP4 необходимо отдельно прогнать с настоящими кадрами, утвержденным текстом и финальными проверками Whisper и loudness. Изменение голосового профиля не заменяет факт- и лицензийные gates и не дает разрешения на публикацию.
