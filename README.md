# Simba — Bon Tours Content System

Приватный репозиторий канонической системы создания контента Simba.

**Источник истины:** `legur/Simba@main`  
**Google Drive `New Simba`:** архив миграции, не рабочий runtime.

## Как работаем в Codex после разделения

Новые задачи ведём в одном из трёх проектов боковой панели. Старый репозиторий `legur/Simba` остаётся точкой справки по общим правилам, базе знаний и истории. Если запрос пришёл в старый проект, по таблице выбираем рабочий проект для задачи.

| Проект в Codex | Папка внутри `work/github-projects` | Репозиторий | За что отвечает |
|---|---|---|---|
| **Simba** | `simba-editorial` | [legur/simba-editorial](https://github.com/legur/simba-editorial) | Посты, новости, тексты для сайта и подписи к роликам. Редакция проводит применимые проверки и собирает комплект «текст + постер». |
| **Rafael** | `rafael` | [legur/rafael](https://github.com/legur/rafael) | Постеры для публикации, самостоятельные иллюстрации, кадры для видео и заказанный дизайн обложек. |
| **Reels Studio** | `reel-studio` | [legur/reel-studio](https://github.com/legur/reel-studio) | Сценарий, раскадровка, референсы Кадра, звук, монтаж и проверка готового видео. |

### Как идут задания и результаты

- **Пост с постером.** Simba готовит текст и после утверждения конкретной редакции или по действующему разрешению передаёт бриф Rafael. Rafael готовит варианты, после выбора возвращает проверенный финальный постер. Ведущий задачи в Simba собирает комплект.
- **Ролик.** Reel Studio начинает с темы или с конкретной редакции текста от Simba. Если нужны новые изображения, студия передаёт Rafael задание с ID сцен и получает кадры с теми же ID. Reel Studio собирает и проверяет видео. Если заказана подпись, Simba готовит её и возвращает ведущему задачи.
- **Отдельный результат.** За текстом или подписью идём в Simba, за изображением в Rafael, за сценарием или видео в Reel Studio. Работа заканчивается на заказанном результате.

Для сквозной задачи назначается один ведущий (`TASK_OWNER`). Он сохраняет ответственность за результат и собирает комплект. Передача соседнему проекту оформляется в общем журнале пакетом с ID задачи и передачи, редакцией, отправителем и получателем, ссылками на материалы, ожидаемым результатом и применимыми утверждениями. Получатель открывает пакет в своей сессии, явно принимает его и возвращает результат с версией и статусом в тот же журнал. Публикация и платные операции по-прежнему проходят по действующим разрешениям.

### Где находятся общая база и журнал

Пути указаны относительно общей папки Simba, в которой находятся этот репозиторий и каталог `work`.

- Единая база знаний: `work/simba-layout-step12/SIMBA KNOWLEDGE BASE`. Все три проекта используют её и действующие общие документы.
- Единый журнал пакетов: `work/project-exchange`. История задачи хранится в `tasks/<taskId>/events.jsonl` внутри этого журнала.
- Путь к общей установке Codex загружает из локальных настроек доверенной папки. Команда `python -B entry.py context` из рабочего проекта показывает его собственные профили и путь общего журнала, без ручной передачи пути.
- Если требуется изменение общей базы, проект передаёт предложение через журнал. Запись в канонический документ выполняет уполномоченный исполнитель по действующему процессу с проверкой результата.

## Базовый порядок загрузки контекста

Маршрутизацию и проверки определяют `AGENTS.md` рабочей точки входа и общие документы.

Базовый старт любой контентной задачи:

```text
AGENTS.md
  → ROUTER_v10.1.md
  → KNOWLEDGE_MAP.md
  → KB_RUNTIME_PROTOCOL.md
  → профильный модуль
  → обязательный KB context
  → результат
```

Для системного изменения дополнительно используется `META-Governance-v8.1.md`.

## Основной production flow

```text
SOURCE / TASK
  → ROUTER
  → PROFILE MODULE
  → KB PREFLIGHT
  → EXECUTION
  → VALIDATION
  → RESULT TO LEO
```

Для рекламного текста Simba:

```text
AI-Маркетолог (если нужна стратегия)
  → Simba
  → INTERNAL_CRITIC_MODE
  → Simba repair/finalize
  → Humanizer (HUMANIZER_PASS)
  → TEXT_READY_FOR_LEO
```

Для Info, Travel, Leo и News готовый пост также проходит Humanizer до выдачи Leo; обязательный Internal Critic им не добавляется. После утверждения именно этой редакции текста:

```text
LEO_APPROVAL
  → APPROVED_TEXT
  → Content Library write-back
  → Rafael
  → 5 previews
  → Leo selects
  → separate final 1:1 render
```

Автопубликации без отдельного утверждённого процесса нет.

## Что является каноническим

Рабочие системные файлы обновляются **на месте**. Git хранит историю версий, поэтому для рабочей версии не создаются `old`, `backup`, `final-final` и параллельные копии.

Исторические материалы в Content Library и Session Logs являются отдельными объектами и сохраняются как история.

## Knowledge Base

Перед содержательной работой система обязана пройти KB PREFLIGHT. Полные правила находятся в:

- `SIMBA KNOWLEDGE BASE/00_CORE/KNOWLEDGE_MAP.md`
- `SIMBA KNOWLEDGE BASE/00_CORE/KB_RUNTIME_PROTOCOL.md`

Content Library используется для стиля, истории решений и контроля повторов — **не** как источник текущих цен, наличия или условий.

## Изменение системы

При изменении Router, META, агента, workflow или Knowledge Base:

1. прочитать `META-Governance-v8.1.md`;
2. изменить канонический файл;
3. сделать Git-коммит;
4. выполнить required `KB_LINT.md`;
5. проверить результат после записи.
