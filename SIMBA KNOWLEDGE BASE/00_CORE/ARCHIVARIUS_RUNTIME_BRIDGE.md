# ARCHIVARIUS RUNTIME BRIDGE

Статус: MANDATORY EXTERNAL-LIBRARY GATE
Дата: 05.09.2026
Назначение: безопасно подключать Archivarius к Simba by Bon Tours без смешивания внешней библиотеки с собственной Knowledge Base.

## 1. Роли систем

`SIMBA KNOWLEDGE BASE` — память и правила Simba by Bon Tours.
`Archivarius` — внешняя библиотека промтов, методологий и визуальных/рабочих референсов.
`TIA` — единственный модуль, который извлекает текстовые паттерны и механики из чужого контента.

Archivarius не заменяет Knowledge Base, TIA, профильные правила агента или подтвержденные факты текущей задачи.

## 2. Жесткая граница TIA

Если задача состоит в том, чтобы:
- разобрать сильный чужой текст;
- понять, почему он работает;
- извлечь hook / ритм / напряжение / CTA / структуру;
- перенести текстовую механику без копирования,

маршрут идет в TIA.

Marketer, Simba, Critic и этот Bridge не выполняют параллельный Pattern Extraction вместо TIA.
Archivarius в таком маршруте может только предоставить исходную карточку/референс, если TIA его запрашивает.

## 3. Runtime access gate

Для Rafael действует широкий доступ к визуальной библиотеке Archivarius, а не закрытый whitelist.

Перед поиском Rafael читает:
1. `00_CORE/ARCHIVARIUS_RUNTIME_TRUSTED.md` — приоритетные, заранее проверенные карточки;
2. `00_CORE/ARCHIVARIUS_RUNTIME_BLOCKLIST.md` — явные запреты.

Алгоритм:
- сначала искать среди `trusted / recommended`;
- затем расширять поиск на все релевантные карточки `Archivarius / 01_Изображения` со статусом `active`;
- исключать blocklist и статусы `draft / needs_fix / archived / duplicate`;
- не использовать текстовую карточку как visual-reference только из-за статуса `active`;
- каждая выбранная карточка должна иметь объяснимую визуальную механику.

`trusted` означает приоритет, а не эксклюзивное разрешение.

Для Marketer/Simba/Critic широкого самостоятельного visual-search нет: текстовая pattern extraction остается зоной TIA.

## 4. Retrieval budget

Archivarius не загружается целиком.

Нормальный runtime:
- найти релевантные карточки;
- сначала проверить trusted-list и blocklist;
- при необходимости расширить поиск на остальные релевантные `active` visual cards;
- shortlist: максимум 3–5 карточек;
- выбрать минимально достаточный набор;
- остановить поиск, когда следующие карточки уже не меняют решение.

Для Rafael предпочтительно 3–5 визуально различающихся карточек: trusted имеют приоритет, но не ограничивают поиск.
Для Marketer — 1–3 методологических карточки только если они реально улучшают решение.
Simba не выполняет самостоятельный поиск Archivarius: получает только уже отфильтрованный `[ARCHIVARIUS_CONTEXT]`, если он вообще нужен.

## 5. Что разрешено переносить

Из выбранной визуальной карточки можно брать только релевантную механику, например:
- композиционный принцип;
- visual hierarchy;
- image treatment;
- работа с типографикой;
- формат/структура prompt-механики;
- методологический прием.

Запрещено автоматически переносить:
- чужие факты;
- чужие цены, даты и условия;
- чужие бренды;
- неподтвержденные claims;
- манипулятивные установки;
- выдуманную экспертность;
- чужой личный опыт;
- текстовые формулировки как будто они принадлежат Leo.

## 6. Runtime modes

### FAST
Для обычных постов, WhatsApp, небольших правок и стандартных постеров.
- минимальный KB-контекст;
- Archivarius используется только при очевидной пользе;
- shortlist до 3 карточек;
- без полного аудита.

### DEEP
Для сложной стратегии, спорных фактов, внешних референсов, системного анализа, авиационных/юридических/высокорисковых задач.
- больше проверки;
- Archivarius shortlist до 5 релевантных visual cards;
- явные допущения;
- TIA вызывается, если нужна текстовая pattern extraction.

### STRICT
Для изменения системных правил, релизной валидации, миграций, QA/Fix Pack.
- формат и целостность важнее скорости;
- проверяются ссылки, зависимости и конфликты;
- после изменения Knowledge Base обязателен `KB-LINT`;
- PASS/WARNING разрешают продолжить; FAIL требует исправления до завершения системного изменения.

## 7. Контракт передачи

Если Archivarius реально использован, Router передает:

```text
[ARCHIVARIUS_CONTEXT]
MODE: FAST | DEEP | STRICT
CARDS:
- AR-ID | allowed_for | extracted_mechanic
EXCLUDED:
- blocklisted / wrong-status / non-visual / conflicting cards
SOURCE_OF_TRUTH:
- current task facts
- SIMBA KNOWLEDGE BASE
```

В пользовательский ответ этот блок не выводится, если Leo отдельно его не попросил.

## 8. Stop / degrade rules

Остановить дальнейший поиск Archivarius, если:
- дальнейшие карточки уже не меняют визуальное решение;
- найденные карточки конфликтуют с Brand/Fact rules;
- материал фактически относится к зоне TIA, а не visual-reference;
- влияние карточки нельзя объяснить конкретной визуальной механикой.

Если Archivarius технически недоступен, это НЕ блокирует Rafael целиком. Зафиксировать `ARCHIVARIUS_STATUS: UNAVAILABLE` и продолжить с YouMind + Visual Rules + текущими фактами.

Если YouMind недоступен, продолжить с Archivarius.

Если недоступны обе библиотеки, Rafael продолжает по собственным Visual Rules и фиксирует `REFERENCE_LIBRARIES_UNAVAILABLE`.

Недоступность самих KB safety-файлов Bridge/Trusted/Blocklist остается `BLOCKED_KB_UNAVAILABLE`, потому что это внутренняя Knowledge Base, а не внешняя reference-библиотека.
