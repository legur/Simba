## Назначение
Сюда попадают содержательные корректировки Лео, которые могут стать постоянным правилом.

## Уже закреплённые корректировки
- клиентский документ должен быть предложением клиенту, а не инструкцией агенту;
- условия рынков США и Израиля разделять;
- если несколько рекламных писем — обрабатывать все;
- после утверждения текста автоматически запускать Rafael;
- Rafael после пяти концепций сразу генерирует все пять визуалов;
- хэштеги в рекламных постах сохраняются, если правила конкретного модуля не изменены;
- не помещать аэропортовые коды и мелкий технический текст на рекламный постер без необходимости;
- повторяющиеся стилистические схемы отслеживать, а не считать частью обязательного фирменного стиля;
- Critic — внешний личный помощник Leo для оценки качества текста; он не является участником production-пайплайна, обязательным gate или согласующим этапом и запускается только отдельно.
- внешний источник без отдельной команды по умолчанию считается `NEW_SOURCE` и обязательно проходит Router; прямое написание поста в обход Router запрещено.

Исходный вариант → Critic был ошибочно включён в production-схему как обязательный этап между генерацией текста и решением Leo.

## Запись 05.09.2026 — source-only default
Задача → устранить обход Router при сообщении, состоящем только из внешнего источника.

Исходный вариант → ссылка/статья без явной команды могла трактоваться произвольно, из-за чего готовый текст создавался напрямую вне установленной схемы.

Корректировка Leo → закрепить предложенный default: внешний содержательный источник без отдельной команды считается `NEW_SOURCE` и автоматически запускает Router.

Обобщённое правило → `SOURCE_ONLY_INPUT → NEW_SOURCE → ROUTER_CORE_PREFLIGHT → ROUTER_TASK_CLASSIFIED → MODULE_KB_PREFLIGHT → PROFILE_MODULE → RESULT_TO_LEO`. Не задавать вопрос о назначении источника, если тип задачи определяется из содержания. Явная команда Leo имеет приоритет. Critic в маршрут автоматически не включается.

Файл, куда правило перенесено → `ROUTER_v10.1.md`, `META-Governance-v8.1.md`, `06_AGENT_WORKFLOWS/CONTENT_PIPELINE.md`, `07_LEARNINGS/DECISION_LOG.md`.

## Запись 30.09.2026 — budetsdelano.ai: learning, не автоматическая правка текущего поста
Задача → обработка содержательного разбора готового поста от budetsdelano.ai.

Исходный вариант → после получения разбора система сразу переписала текущий экспертный пост, хотя Leo не просил новую редакцию.

Корректировка Leo → «Ты не должен его переделывать, а должен учесть замечания и в будущих постах учитывать это. У тебя есть правила на этот счёт».

Обобщённое правило → содержательный разбор budetsdelano.ai является входом Feedback Learning: сохранить как CASE, обновить совпадающие PATTERN и учитывать их в будущих релевантных Facebook-постах. Сам по себе такой разбор НЕ является командой переписать текущий/утверждённый пост. Текущий пост изменяется только по явной команде Leo.

Файл, куда правило уже относится → `ROUTER_v10.1.md` / глобальный `FEEDBACK LEARNING`; данная запись фиксирует ошибку исполнения, а не создаёт новое архитектурное правило.


## Запись 04.10.2026 — конкретный объект может оставаться гиперболой

Задача → уточнение правила рекламных сравнений цены.

Исходный вариант → система считала сравнения с реальными товарами/услугами автоматически проверяемыми claims.

Корректировка Leo → «дешевле двух ужинов в Тель-Авиве» — хорошее рекламное сравнение; аудитория понимает его как гиперболу, а не бухгалтерское утверждение.

Обобщённое правило → классифицировать по ожидаемому чтению в контексте, а не по наличию конкретного объекта. Очевидная гипербола допустима без отдельного фактчека; проценты, точная сумма экономии, история цены и буквальное сравнение требуют источника.

Статус → прямое уточнение постоянного правила; синхронизировано в STYLE_LEO, FACTS_FRESHNESS_PRICING, AI-Marketer и Simba.
