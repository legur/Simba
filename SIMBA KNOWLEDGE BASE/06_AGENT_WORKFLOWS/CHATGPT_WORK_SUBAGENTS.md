# CHATGPT WORK SUBAGENTS — независимые редакционные роли внутри ChatGPT

**Scope:** только текст Simba CORE. **Исполнительная среда:** ChatGPT **Work**, если в этой сессии функция субагентов реально доступна. Не Codex CLI, локальный компьютер, MCP-раннер, Notion/другой внешний агент и не OpenAI Responses API. GitHub хранит правила, Work выполняет делегированные агентные шаги.

**Основание:** прямое решение Leo «работаем сугубо изнутри чата» и следующее «делай». Это расширение `CHATGPT_NATIVE_EDITORIAL.md`, не новый автор/публикационный контур.

**Важная граница:** этот файл сам по себе **не создает и не запускает** субагентов в обычном Chat-режиме. Установленный плагин и GitHub-PR не доказывают, что Work активен или что у аккаунта есть доступ. Если native delegation отсутствует, использовать `CHAT_NATIVE_SINGLE_MODEL` и честный `BLOCKED_INDEPENDENT_EXECUTOR_UNAVAILABLE` для требований независимого прохождения. Не подставлять synthetic `simba_core_handoff_selftest` или называть три стилевых прохода тремя агентами.

## I. Проверка среды перед запуском

1. Пользователь остается в ChatGPT. При доступном **Work** агент-оркестратор просит **внутреннее делегирование субагентам**; не просит у Leo PowerShell, API-ключ, Windows ACL, URL собственного сервера, перехода в сторонний сервис или ручной копипаст между отдельными диалогами.
2. Перед задачей прочитать текущие `ROUTER_v10.1.md`, `KNOWLEDGE_MAP.md`, `KB_RUNTIME_PROTOCOL.md`, `CHATGPT_NATIVE_EDITORIAL.md`, профиль Simba и правила Critic/Humanizer, необходимую BRAND/AUDIENCE/FACTS/CONTENT/LEARNINGS KB. Недоступный обязательный файл → `BLOCKED_KB_UNAVAILABLE` с путем; не скрывать этот факт.
3. Проверить, можно ли **вызвать** субагента в этой сессии, а не только прочитать описание функции. Запрос на делегирование в тексте инструкции не является ответом агента. Если отсутствует Work/native subagent capability → без спама повторными попытками статус `BLOCKED_INDEPENDENT_EXECUTOR_UNAVAILABLE`.
4. Для первой проверки использовать **один синтетический туристический текст** без цен, дат, бронирования, клиентских данных и коммерческих обещаний. Для реального текста обязательны source-resolution, TIA, факт-проверка и контракт количества вариантов Simba.

## II. Реальное делегирование и разделение контекста

Оркестратор владеет процессом, а не выдает собственный текст за результат автономных ролей. Зависимые шаги выполняются **последовательно**, а не одновременно.

**Роль 1: субагент Simba (автор)**

Передать: роль `Simba`, цель и канал, подтвержденные факты/источники, актуальный профиль `Симба (Писатель)/Simba-v5.0.md`, стилевые правила и релевантный KB-контекст, ограничения, количество вариантов, отсутствие разрешения публикации. Инструкция субагенту: «Создай одну точную тестовую редакцию без оценки себя от имени Critic. Верни полный текст и идентификатор редакции; не называй ее APPROVED/PUBLISHED». Оркестратор читает **фактический результат субагента**, закрепляет точные байты UTF-8 и при доступности вычисляет SHA-256 (не придумывать хеш).

**Роль 2: отдельный субагент Critic (контроль)**

Создать **отдельную** делегированную сессию, не тот же сеанс Simba под другим заголовком. Передать **точный** авторский текст и его проверенный SHA-256 (если доступен), исходный бриф, цель, актуальные `Critic/Critic-5.7.md`, факты/правила; **не** передавать фиктивный предварительный PASS. Инструкция: «Проверяй только эту точную редакцию, верни `PASS`/`REVISE`, оценку 0–10, список конкретных блокеров и указание на точный вход; `PASS` только при выполнении обязательных критериев Critic и пороге 8/10». Подтвердить действительный ответ в activity/результате, а не из описания инструмента.

Если `REVISE`: передать замечания **субагенту Simba** для новой редакции; вновь послать полную новую редакцию Critic. При трех подряд безрезультатных ремонтах → `BLOCKED_CRITIC_NO_PROGRESS`, не фиктивный PASS. После PASS выполнить авторский finalize через Simba и **повторить Critic**, если изменились байты текста.

**Роль 3: отдельный субагент Humanizer (языковая редактура)**

Только после проверенного Critic PASS для той же версии. Передать точный текст и `Симба (Писатель)/Humanizer-v1.4.md` + стиль/антистиль. Инструкция: «Минимально убери AI-маркеры; сохрани все факты, интонацию, CTA и смысл. Верни только полный текст; укажи, менялись ли байты и/или смысл». Сравнить точный вход и выход. Если изменились байты, прогнать новую редакцию через отдельного Critic; при `REVISE` возврат Simba и весь применимый цикл, а не silent PASS. При смысловой правке также вернуть ее Simba для авторского подтверждения и повторного Critic.

**Последовательность:**

`SOURCE/KB_PREFLIGHT → WORK_SUBAGENT_SIMBA(draft) → WORK_SUBAGENT_CRITIC(exact draft) → [WORK_SUBAGENT_SIMBA(repair) → WORK_SUBAGENT_CRITIC(exact repair)]* → WORK_SUBAGENT_SIMBA(finalize) → WORK_SUBAGENT_HUMANIZER(exact text) → [WORK_SUBAGENT_CRITIC(exact final)] → USER_REVIEW`.

Для производственных задач с несколькими вариантами повторить проверку **для каждого** варианта по действующему Simba/Copywriter contract. Нельзя выдать PASS для одного варианта всем вариантам.

## III. Доказательства и статусы

- **Выполненный native subagent:** в ChatGPT Work видна фактическая отдельная activity/thread и получен результат этого шага. Зафиксировать роль, видимую ссылку/ID задания **если интерфейс предоставляет**, время (если доступно), имя актуального профиля, точную версию входа/выхода и связанный verdict. Не выдумывать идентификатор, время, SHA, вызов, стоимость или provider receipts.
- **Binding:** сравнить вход Critic с точным выходом Simba (и после Humanizer), а не только с пересказом. При наличии инструментов хеширования вычислить SHA-256 по UTF-8. При отсутствии технической проверки не объявлять `REVISION_HASH_VERIFIED`.
- **Минимальное условие `CHAT_NATIVE_VERIFIED_ROLE_TOOLS`:** реально наблюдаемые отдельные запуски и результаты Simba, Critic и Humanizer, вход/выход каждой ревизии сопоставлены, финальная версия не осталась без Critic, обязательные KB/source/fact/TIA gates завершены. Эта метка означает только наблюдаемую редакционную цепочку **в данной сессии**, не криптографическую аутентификацию провайдера, не `APPROVED_TEXT` и не разрешение публикации.
- **Недостаточно evidence:** `CHAT_NATIVE_WORK_SUBAGENTS_EVIDENCE_INCOMPLETE` и точный отсутствующий шаг; текст можно показать как черновик, но не повышать статус. Нет инструментов Work → `BLOCKED_INDEPENDENT_EXECUTOR_UNAVAILABLE`.
- **Без отдельного API billing:** субагенты используют функции и лимиты подписки ChatGPT Work при наличии доступа; это может расходовать лимиты/токены продукта, но **не требует** внешнего `OPENAI_API_KEY` и не дает разрешения на отдельные платные API-вызовы. Не обещать бесплатность без ограничений.
- Никакой subagent не может самостоятельно утверждать текст за Leo, писать в `APPROVED` или публиковать. GitHub Issues — только очищенная техническая информация, без приватного текста или данных клиента.

## IV. Критерий приемки первого реального пилота

Один заранее выбранный синтетический бриф; оркестратор из ChatGPT Work действительно делегирует **три** отдельных специализированных субагента, получает их outputs, контролирует финальную ревизию. В activity видны три отдельных выполнения. В итоговом сообщении показать точный текст и короткий статус, какие subagents действительно вызваны, что проверено и что **не** проверено. До такого запуска статус реализации **`WORK_NATIVE_SUBAGENTS_CONTRACT_READY_NOT_EXECUTED`**, а не успешный live-test.

**Официальная функция:** ChatGPT Work с native subagents у поддерживаемых аккаунтов; в обычном Chat режиме доступность не подразумевается. Источник — OpenAI ChatGPT Learn, раздел «Subagents» (`https://learn.chatgpt.com/docs/agent-configuration/subagents`). Не заменять native Work исполнение локальным Codex CLI или инструментами сторонних AI-платформ.
