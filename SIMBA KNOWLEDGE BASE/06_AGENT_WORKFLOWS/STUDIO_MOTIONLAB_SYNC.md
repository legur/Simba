# Studio ↔ Simba Motion Lab — единый контракт подготовки монтажа
Версия: 2026-11-10 · Уточнение Leo: готовые клипы — результат Ф2У (A2E) · Статус: PROCESS_ALIGNED / IMPLEMENTATION_PARTIALIAL
Ответственные контексты: отдельный чат **Studio** (подготовительный интерактивный модуль) и
**Simba Киностудия / PR #105** (GitHub/Google Drive, контракты этапов и производственный монтаж).
Этот файл в **main** — общая точка сверки решений. Наличие документа **не означает**
автоматического обмена сообщениями между чатами или работоспособности live-host.

## 1. Единая цель и границы

Studio/Motion Lab **помогает монтажеру собрать готовый ролик**: показывает
переходы, субтитры, экранный текст, движения, графику, маршруты,
музыкальные акценты, режиссерские сочетания и дает пользователю
выбрать конкретные настройки. **Это НЕ видеоредактор/рендерер** и не
замена `Монтажер Клод` / `integrations/video/`.

**Вход Motion Lab — готовые анимированные клипы (обычно 5–15 секунд),
полученные в результате Ф2У (A2E).** Входом Ф2У служат ранее
утвержденные исходные изображения/кадры Рафаэля. Фотографии
не образуют самостоятельную ветку монтажа в этом процессе:
их сначала согласовывают и анимируют через Ф2У.

**Одна производственная цепочка:**
Сценарист → Рафаэль (статичные кадры) → Ф2У/A2E (готовые клипы)
→ проверка и архив MP4 → озвучка/музыка → Studio/Motion Lab
(выбор переходов, субтитров, титров и темпа) → Монтажер Клод
(единый готовый MP4) → VIDEO_QA → утверждение Leo.
Никаких повторных Ф2У/платных вызовов при передаче клипов
монтажеру. Ф2У запускается только в пределах уже выбранного
и разрешенного объема/лимита.

Перед вызовом интерфейса автоматическая среда передает актуальные
сценарий/очередность, идентификаторы проверенных исходных медиа,
их доступность, длительность и ограничения, утвержденные голос/
музыку и 3 полных режиссерских решения. После выбора среда принимает
параметры и передает их **тому же существующему монтажеру**,
который собирает MP4 и делает QA.

## 2. Единый источник монтажных клипов — результат Ф2У

| Этап | Что поступает | Что получается |
|---|---|---|
| Рафаэль | Утвержденный сценарий, раскадровка и кадры | Статичные исходные изображения |
| Ф2У / A2E | Утвержденные кадры и выбранные промпты анимации | **Готовые короткие видеоклипы**, обычно 5–15 с |
| Архив и проверка | Реальные task ID и клипы A2E | Проверенные MP4 с длительностью, SHA-256 и приватными Drive ID |
| Studio / Motion Lab | **Только подтвержденные готовые клипы Ф2У** + сценарий, согласованная озвучка и музыка | Выбранный монтажный JSON для каждого клипа |
| Монтажер Клод | Подтвержденные клипы, выбранные эффекты и согласованное аудио | Единый финальный MP4 и технический QA |

**Не создавать отдельный маршрут `READY_MEDIA`.** Предыдущее
предположение, будто готовые клипы и Ф2У — независимые источники,
было ошибкой. В текущей Киностудии готовые клипы являются
**выходом Ф2У**. Название `MONTAGE_PREPARE` можно использовать
как описание входа в Motion Lab, но оно не является дополнительным
обязательным этапом в `handoff.py`.

## 3. Кто и что выполняет

1. **Simba/Киностудия — оркестратор**: ID проекта, источник истины
   `campaigns/<id>/project.json`, SHA-256 оригиналов, тройки
   вариантов, выбор Leo, чекпоинты и маршрутизация.
2. **Режиссерская подготовка Studio/Motion Lab (PR #112 merged, после Ф2У)**:
   предлагает и отображает три *существенно разных* варианта
   обработки исходных сцен, дает изменить конкретные переходы,
   субтитры, титры, камеру, графику и темп; возвращает подробный
   JSON выбранного варианта по уже существующему
   `bontours.motionlab.storyboard.launch/v1` /
   `bontours.motionlab.storyboard.selection/v1`.
   Не генерирует клипы, не синтезирует голос, не публикует.
3. **Проверенный приемник (PR #105 draft)**: проверяет
   `request_id/project_id/expected_input_fingerprint`,
   исходные asset ID, длительности и выбор; сохраняет
   выбранные настройки в `stage_handoffs.edit_choice`.
   `DRAFT_NOT_DELIVERED` не является согласием пользователя.
4. **Монтажер Клод**: по выбранному сценарию, реальным исходникам,
   согласованному голосу и лицензированной музыке собирает
   единственный финальный вариант MP4 через действующие
   `integrations/video/`, включая настоящие переходы, экранный
   текст и субтитры. Не подменяет согласованный голос; если
   клип уже содержит синхронизированную речь, сохраняет режим
   собственного звука и не накладывает синтез поверх без решения.
5. **VIDEO_QA**: фактический MP4, совпадение речи и субтитров,
   отсутствие обрезанных реплик, читаемость, тайминги, звук,
   целостность кадров и итоговый preview; решение Leo и
   публикация — отдельно.

**Выбор конкретного варианта = одобрение его выполнения в пределах
показанного объема/стоимости.** Не спрашивать повторно о том же
запуске. Одобрение монтажа не дает права запускать
непредусмотренную платную генерацию или автоматически публиковать.

## 4. Данные между компонентами

**Вызов**:
- `project_id`, `request_id`, `stage=edit_choice`,
  `expected_input_fingerprint` текущего канонического проекта;
- `scenes[]` в утвержденном порядке с `scene_id`,
  `asset_id` проверенного готового MP4 Ф2У (не временный URL),
  действительной длительностью полученного клипа (обычно 5–15 с),
  безопасным preview URL **только** при наличии разрешенного,
  действительно доступного публичного предпросмотра;
- `options[3]`: полное оформление каждой сцены (camera,
  transition, subtitle style + word motion, title, экранный текст,
  графика, темп) и понятное визуальное сравнение;
- отдельные references на уже утвержденный текст/голос, аудио,
  музыкальный трек, лицензии, согласованный aspect ratio и
  лимит ролика ≤60 секунд. **Приватные медиа-файлы, персональные
  данные, signed URL, токены и коммерческий текст не публиковать
  в публичных Issue или на статическом сайте.**

**Возврат**:
- `SIMBA_MOTIONLAB_SELECTION` с теми же ID/receipt,
  выбранным номером 1–3 и настройками **для каждой сцены**;
- существующий `motionlab_selection.validate` + проверка
  в действительном проекте; запись в защищенное хранилище,
  новый `stage_handoffs.edit_choice`, запись выбранного plan SHA;
- `SIMBA_MOTIONLAB_ACK` **только после** durable-save у
  реального аутентифицированного host. Офлайн JSON-экспорт
  помечен `DRAFT_NOT_DELIVERED`; без backend он не может быть
  утвержден даже при ручной правке флага;
- при ошибке/устаревшем receipt: `REJECTED`, без silent
  approval, без запуска рендера/платного TTS/A2E.

Дополнительные параметры `trim/window` и `graphics/rhythm` требуют
**согласованного обратно совместимого расширения** существующих
`launch/v1`/`selection/v1` либо отдельной `v2`; в базовой цепочке
`source_kind` не нужен, поскольку все входные клипы уже являются MP4 Ф2У. Сама веб-страница
Motion Lab сегодня при отсутствии утвержденного preview может
показывать demo-фотографию: это **не** предпросмотр реального исходника.

  из-за `403 VELO.APP_PROJECT_READ`. Слияние GitHub PR
  не доказывает, что Wix сайт обновлен.

## 6. Разграничение разработки и порядок продолжения

**Studio (чат редактора)** отвечает за UX подготовки:
библиотеки, выбор трех решений, preview/таймлайн, назначение
переходов/субтитров по сценам, режимы и точный JSON.
Не реализует вторую систему TTS/A2E или рендерер.

**PR #105 (чат Киностудии)** отвечает за backend:
проверенные клипы Ф2У из приватного Drive, привязку
`stage_handoffs.a2e_clips` и `voice_music`,
безопасную передачу launch, валидацию выбора, durable-save,
owner-authenticated write-back и маршрут к Монтажеру Клоду.
**Отдельную ветку `READY_MEDIA` не разрабатывать.**
Не дублировать библиотеки эффектов и рендерер.

**Оба направления** используют **этот файл в main** как общую
спецификацию. Новые решения сначала меняют контракт с
названием версии, затем каждый модуль адаптируется и проходит
совместимые тесты. Не редактировать один и тот же JS/Python из
двух независимых веток без синхронизации Git.
