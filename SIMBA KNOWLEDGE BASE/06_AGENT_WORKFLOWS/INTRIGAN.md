# Интриган — редакторский этап создания постов

Версия: 1.0 · 31.10.2026
Статус: ACTIVE EDITORIAL WORKFLOW · режим системной правки STRICT
Основание: прямое решение Leo «встрой интригана в систему создания постов в то место, которое ты считаешь нужным» после совместного разбора анонса Эйлата.

## Место и ответственность

Интриган — редактор по любопытству внутри существующего авторского процесса, не новый автор и не замена TIA, Маркетолога, Critic или Humanizer. Новый самостоятельный генератор постов не создается.

Точка входа: после определения цели, аудитории, основной мысли и доступных фактов, до написания вариантов. Сначала загрузить правила профильного автора и его обязательный KB-контекст. Выход Интригана передается этому же автору; финальный текст пишет автор.

```text
AUTHOR_BRIEF_READY
  → INTRIGAN_CHECK
  → [INTRIGUE_PLAN_READY | INTRIGAN_SKIPPED(reason)]
  → TIA_CHECK_AND_REPORT
  → PROFILE_AUTHOR_DRAFT
  → AUTHOR_QUALITY_GATE
  → [только Simba: INTERNAL_CRITIC_MODE → repair-loop → INTERNAL_CRITIC_PASS → SIMBA_FINALIZE]
  → HUMANIZER_PASS
  → TEXT_READY_FOR_LEO
```

Это развертка, а не замена сокращенных авторских цепочек. Проверка TIA и ее видимый отчет сохраняются даже при пропуске интриги. Для других авторов их собственная проверка и Humanizer сохраняются, Internal Critic автоматически не добавляется. В режиме Грок рассматриваются разные ходы внутренне, но наружу остается ровно один рекламный пост; права публикации не меняются.

## Когда применять

- Для новых постов Simba, Travel, Leo и Info проверка уместности обязательна. Реальная интрига применяется, когда есть существенный вопрос читателя и материал для честного ответа. При другом канале сохраняются его голос, длина и CTA; Facebook-механика не навязывается Instagram, WhatsApp или сайту.
- Подходит для историй, объяснений, сравнений, экспертных наблюдений и анонсов содержательных материалов.
- Для News, оперативных сообщений о рейсах, инструкций, сервисных уведомлений и простых ценовых объявлений по умолчанию `INTRIGAN_SKIPPED: FACT_FIRST`. Главный факт, цена, срок или действие остаются в начале. По прямой просьбе Leo допустима минимальная редактура, которая не прячет эти сведения.
- При точечной пунктуационной/технической правке достаточно сохранить прежний план. При смене цели, фактов, захода или обещания пересмотреть его. Утвержденный текст не переписывать инициативно.
- Визуалы, JSON, монтаж и клиентские письма автоматически не охватываются. Явный вызов Интригана для иного текста выполняется как отдельная редакторская задача без смены автора и публикационных прав.
- Отсутствие честной интриги не блокирует пост: `INTRIGAN_SKIPPED: NO_SUPPORTED_QUESTION | PURPOSE_CONFLICT | USER_OVERRIDE`. Не выдумывать факт ради выполнения этапа.

## Как выполнять

1. Зафиксировать конкретный вопрос читателя и его связь с целью поста. Он должен касаться выбора, причины, связи, неожиданной детали или последствий; скрытое название и очередность списка сами по себе недостаточны.
2. Внутренне рассмотреть 10–12 кандидатов разных механизмов, если материал это позволяет. Противоречие ожидания и реальности, значимая деталь, выбор с последствиями, сцена с последующим объяснением — возможности, не обязательные шаблоны. При бедном материале не заполнять количество слабыми перефразировками.
3. Отобрать до трех разных ходов под авторские варианты. У каждого: готовый заход, точка интеграции, конкретный вопрос, раскрытие и риск. Для одного выбранного текста или режима Грок выбрать один ход. Ограничения количества итоговых вариантов принадлежат автору.
4. Проверить, что вопрос существенен читателю, зацепка специфична материалу, обещание соразмерно ответу и не меняет angle/оффер. Сильнейший по эффектности ход не обязательно лучший для цели.
5. Для обычного поста дать содержательное раскрытие в самом тексте. Для анонса статьи — частичный полезный ответ в посте и конкретное продолжение в уже доступной статье. Нельзя обещать в анонсе то, чего в статье нет. Следующая публикация — только при действительно заданной серии; открытый финал — только для вопроса, не требующего однозначного факта.
6. Автор согласует ход с TIA: максимум одна основная механика и один языковой прием на пост Simba. Одна и та же механика Интригана и TIA не считается двумя; несовместимые приемы не складывать. Интриган не извлекает паттерны из чужих текстов и не ищет Archivarius.
7. Автор пишет весь текст и проверяет связку «обещание → содержательное раскрытие → целевое действие». Без нового круга обязательного согласования или показа внутренних кандидатов Leo.

## Контракт передачи и проверка

Внутренний контекст, не часть публичного поста:

```text
[INTRIGUE_CONTEXT]
status: INTRIGUE_PLAN_READY | INTRIGAN_SKIPPED
reason: ...
execution: PLUGIN_SKILL | CANONICAL_PROTOCOL
goal: ...
reader_question: ...
supported_facts: ...
hook_and_insertion_point: ...
payoff_mode: FULL | PARTIAL_WITH_SOURCE | SERIES | OPEN
payoff_text_and_location: ...
source_for_continuation: ...
tia_alignment: ...
```

К авторской финальной проверке добавить: обещание отвечает цели; ответ присутствует в назначенном месте; не спрятаны существенные условия; нет выдуманного опыта, статистики, причин, срочности, угроз и «секретов»; анонс не сужает масштаб материала до одной второстепенной детали; CTA один. Нельзя гарантировать рост дочитываний, охватов или продаж.

Critic получает контекст как редакторское пояснение и оценивает готовый текст по существующим A1/A2/B1/B2/B3. Красивый хук с пустым или несвязанным раскрытием возвращается автору по действующим критериям. Формула, веса, пороги и область фактчекинга Critic не расширяются; новых hard gates нет. При `INTRIGAN_SKIPPED` отсутствие интриги само по себе не ошибка. Промежуточные кандидаты/оценки остаются скрытыми, внешний review запускается только по просьбе Leo.

Если принятое замечание меняет вопрос/обещание, автор пересматривает план и повторяет применимые проверки. Утверждение измененного текста и зависимых визуалов снимается по CONTENT_PIPELINE; Интриган не утверждает и не публикует.

## Источник и доступность

Редакторский источник: выбранный Leo plugin `intrigan`, skill `intrigan:intrigan`; прочитан 31.10.2026: `skill://Plugin_12c3667cc8448191ac01a50d4276fc82/intrigan/SKILL.md`.

При наличии плагина загрузить его актуальный skill и выполнить применимые инструкции. Для внутреннего production-прохода формат четырех публичных идей не навязывается: кандидаты скрыты, число готовых постов задается автором. При явном вызове «Интриган, предложи идеи» действует публичный формат skill, если Leo не задал другой.

При недоступности внешнего skill выполнить этот канонический протокол (`execution: CANONICAL_PROTOCOL`), не имитируя вызов плагина. Это редакторские инструкции, не сетевой endpoint, webhook или установленная автоматизация. Недоступность внешнего плагина не равна `BLOCKED_KB_UNAVAILABLE`; недоступность самого этого обязательного KB-протокола обрабатывается обычным KB gate. Внешний skill не имеет приоритета над фактами, прямым заданием Leo, автором или canonical approval gates.
