# CHATGPT_NATIVE_EDITORIAL — канонический режим редакции внутри чата

**Статус:** активный маршрут для текстовых редакционных задач Simba CORE с 18.11.2026 по прямому решению Leo.  
**Область:** посты/текст, проверка редакций и handoff. **Не** Киностудия, Rafael, video, рассылки, публикация и API-оркестратор.  
**Источник истины:** `legur/Simba@main` (GitHub хранит канонические инструкции, не исполняет агентов).

## 1. Где исполняется задача

- **ChatGPT — единственная пользовательская среда**: Leo дает задачу, читает варианты, видит результаты проверки и утверждает точную редакцию в этом же чате.
- Подключенные инструменты ChatGPT (включая GitHub, если он доступен) — средства **чтения/записи и передачи проверяемых результатов**, а не самостоятельные авторы или доказательство вызова редакционного агента.
- **Не требовать** от Leo PowerShell, запуска Python, локального MCP/stdio, OpenAI API key, `SIMBA_CORE_ALLOW_BILLABLE`, приватной Windows-папки или перехода в отдельное приложение для обычного текстового процесса.
- Прежние `plugins/simba-core/server/` и `integrations/core/editorial_live_runner.py` — **опциональная legacy-диагностика и отдельный opt-in пилот**, не обязательная стадия чата. Наличие этих файлов не разрешает платные вызовы. Команды «делай», «дальше» и «готово» не дают разрешения на внешний API-биллинг.
- Не обещать работу «в фоне», создание отдельных автономных экземпляров или инструменты, которых нет в текущем вызове ChatGPT.

## 2. Обязательное чтение и маршрутизация

Сначала текущая версия `ROUTER_v10.1.md`, затем
`00_CORE/KNOWLEDGE_MAP.md` и `00_CORE/KB_RUNTIME_PROTOCOL.md`, нужный профиль, его обязательные KB-слои и профильные проверки. Для Simba — `Симба (Писатель)/Simba-v5.0.md`, `Critic/Critic-5.7.md`, `Симба (Писатель)/Humanizer-v1.4.md`; для поста соблюсти Intrigan, TIA, факт-контроль и правила количества вариантов по действующим профилям.

При наличии GitHub connector читать **реальные файлы** из `legur/Simba@main` в этом чате и фиксировать название, версию/commit, доступность. Не заменять недоступный обязательный файл памятью. Отсутствующий обязательный KB-файл → `BLOCKED_KB_UNAVAILABLE` и название файла; это не просьба установить локальный MCP. При непроверенных динамических данных → `BLOCKED_FACTS` для утвержденного/публикуемого статуса. Уже присланные Leo факты/файлы не запрашивать повторно.

## 3. Два режима исполнения — не смешивать

### A. `CHAT_NATIVE_SINGLE_MODEL` (доступен без отдельных агентных инструментов)

ChatGPT последовательно применяет **реально прочитанные** инструкции авторского профиля, затем выполняет самопроверку по правилам Critic, возвращает редакцию авторскому этапу при обнаруженной проблеме и выполняет языковую правку по Humanizer. Для смысловой правки перепроверяет итоговый текст по применимым критериям.

Это **один исполняющий ассистент и несколько редакторских проходов**, а не три независимо запущенных агента. Технически корректная маркировка: `CHAT_DRAFT_SELF_REVIEWED_INDEPENDENCE_UNVERIFIED`. Можно показывать готовый для **обсуждения и выбора** текст, но запрещено приписывать независимые `INTERNAL_CRITIC_PASS`, `HUMANIZER_PASS`, `EXECUTOR_EXECUTED` отдельных агентов, `TEXT_READY_FOR_LEO` (как production gate), `APPROVED_TEXT` или `PUBLISHED` на основании одной самопроверки.

Если пользователь просит реальный независимый Critic/Humanizer, а отдельного инструмента нет, текст остается черновиком; невыполненные независимые этапы обозначить `BLOCKED_INDEPENDENT_EXECUTOR_UNAVAILABLE`. Не выдавать без пояснения имитацию нескольких голосов за три вызова.

### B. `CHAT_NATIVE_VERIFIED_ROLE_TOOLS` (только если доступны отдельные инструменты)

PROCESS_OWNER вызывает доступные **раздельные** инструменты выбранных ролей в контексте ChatGPT и получает явные фактические ответы. Каждая передача содержит краткий бриф, прочитанные правила, точный текст + SHA-256 редакции, критерии QA и ограничения. Результат роли читается обратно до следующей стадии; отказ/ошибка исполнения не заменяются выдуманным текстом. При отсутствии отдельного инструмента **не объявлять** режим B исполненным.

Минимальный порядок:
`SOURCE_RESOLVED → SIMBA_DRAFT → CRITIC_CHECK(exact revision) → [SIMBA_REPAIR → CRITIC_CHECK]* → SIMBA_FINALIZE → HUMANIZER_EDIT → [CRITIC_RECHECK if exact bytes changed] → LEO_REVIEW`.

Для других авторов применять их собственные QA-гейты (не добавлять им автоматически Internal Critic).

**Evidence B:** на каждый внешний/отдельный исполнительный вызов нужны инструмент/канал, факт вызова, проверенный output/response, входной и выходной SHA-256, актуальная ревизия KB, связанный Critic verdict и результат повторной проверки. Список названий ролей, Markdown, synthetic selftest и metadata `DECLARED_*` не считаются evidence. Если реальных инструментов в сессии нет, перейти к A с честной пометкой либо `BLOCKED_INDEPENDENT_EXECUTOR_UNAVAILABLE`, если требовалась именно независимость.

## 4. Результат и утверждение

- `OFFLINE_HANDOFF_CONTRACT_OK_NOT_AGENT_EXECUTION` из локального Python теста — подтверждение **синтетической схемы**, не живого редколлегиального исполнения. Не запускать его для новой задачи как замену работы в чате.
- `CHAT_DRAFT_SELF_REVIEWED_INDEPENDENCE_UNVERIFIED` — пригодный для чтения/правок текст с самопроверкой одного ChatGPT; **не production PASS**.
- `CHAT_NATIVE_VERIFIED_ROLE_TOOLS` и точный итоговый текст + receipts могут перейти на **выбор Leo**, только если остальные обязательные gates выполнены и факты подтверждены.
- Одобрение Leo — **отдельное явное решение для конкретной редакции**; одобрение текста не означает разрешение публикации. `PUBLISHED` — только по реальному подтвержденному размещению.
- GitHub write-back выполняется **только** после фактического readback и при подходящих правах. Публичные Issues/PR не должны содержать приватных клиентских данных, закрытых Drive ссылок, неутвержденных материалов и секретов.
- Киностудия и визуальные workflows не изменяются этим контрактом.

## 5. Контракт ответа пользователю

Не превращать работу над контентом в просьбы открыть консоль. Доставлять в этот чат текст или объяснимый блокер. Для редакционных вариантов сохранять штатные требования модулей. Показывать сведения о внутренних проверках только при запросе или при существенном блокере. Внутри одного текущего задания не требовать повторного разрешения на уже утвержденный **бесплатный** шаг.

**Проверочная фраза:** «Работа ведется внутри ChatGPT. Текущий режим: A (один ассистент, редакционные проходы) или B (отдельные подтвержденные инструменты). Нет API-вызовов, автопубликации и неподтвержденных PASS».
