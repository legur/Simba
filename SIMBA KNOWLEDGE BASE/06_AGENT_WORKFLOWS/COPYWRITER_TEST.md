# COPYWRITER TEST — дополнительный вариант внутри Simba

Версия: 1.0 · 31.10.2026
Статус: TEST_ENABLED, дополнительный drafting adapter, не новый production-автор.
Источник: прямое решение Leo от 31.10.2026 добавить Копирайтера-универсала в тестовом режиме и сделать дополнительную версию анонса Эйлата.

## Границы

По умолчанию для нового обычного задания Simba: три штатных самодостаточных варианта плюс один отдельно подписанный «Тестовая версия Копирайтера-универсала». Не подменять им один из трех. Явный запрос только тестовой версии означает один новый текст без повторения остальных. Один кандидат на запрошенный пост и канал; не создавать незапрошенные версии для сайта, WhatsApp или других площадок. Если бриф явно требует Facebook и Instagram, адаптировать этот кандидат к каждому из двух каналов.

GROK_ADS_MODE всегда сохраняет один пост; автоматический тест отключен. Точечная правка выбранного текста, «без вариантов», оперативная новость и маршруты иных авторов не получают автоматически дополнительный кандидат. Явный запрос сравнения обрабатывается отдельно, без изменения их исходных требований. Команды «выключи тест копирайтера» / «без копирайтера» имеют приоритет; постоянное отключение записать в канонический runtime, разовое касается текущей задачи.

## Исполнение

1. Использовать тот же подтвержденный бриф, аудиторию, канал, цель, факты, ограничения, CTA и контактный формат, что и Simba. Выполнить применимые KB PREFLIGHT, INTRIGAN_CHECK и TIA_CHECK_AND_REPORT до написания. Интриган дает план раскрытия, не новые факты.
2. Прочитать доступный skill Копирайтера-универсала: `skill://Plugin_0ff3ca257f0881918a70cd7d6e63ef6a/instructions/SKILL.md` через установленный пакет `c0/instructions` или его актуальный идентификатор в каталоге. Не считать внешнюю LLM/API вызванной: это применение прочитанных инструкций skill текущим исполнителем. Фиксировать PLUGIN_SKILL только после реального чтения и исполнения.
3. Взять из skill принципы: теплый экспертный голос, ясная продающая структура TEA/4U/AIDA, конкретный заголовок, отсутствие клише и давления. Framework и длина определяются задачей. Если бриф достаточен, не останавливать работу вопросами: AIDA и мягкая продажа 3/10 — стартовая гипотеза. Фиксированный объем 2000–3000 знаков не навязывать короткому анонсу. Прямое указание Leo выше skill. Чужой Telegram-канал и постороннюю рекламу не добавлять.
4. Создать один дополнительный кандидат с самостоятельной подачей, без механической перестановки штатного текста. Simba завершает редакцию, проверяя точность, голос и пригодность под заданную цель. Происхождение не скрывать: `DRAFT_WRITER=COPYWRITER_UNIVERSAL`, `TEXT_EXECUTOR=Simba`, `COPYWRITER_EXECUTION=PLUGIN_SKILL`.
5. Каждый готовый кандидат проходит тот же авторский Quality gate → INTERNAL_CRITIC_MODE / SIMBA_REPAIR → INTERNAL_CRITIC_PASS → SIMBA_FINALIZE → HUMANIZER_PASS. Служебные баллы скрыты. Существенная правка возвращает к соответствующим проверкам. Тестовый ярлык не заменяет gates.
6. Показать отдельный подписанный дополнительный текст. Выбор и утверждение принадлежат Leo; тест не дает новых прав отправки или публикации.

Состояния: COPYWRITER_TEST_CHECK → [COPYWRITER_SKILL_LOADED → COPYWRITER_DRAFT_READY → SIMBA_AUTHOR_FINALIZATION → AUTHOR_QUALITY_GATE → INTERNAL_CRITIC_PASS → SIMBA_FINALIZE → HUMANIZER_PASS → TEST_VERSION_READY | COPYWRITER_TEST_SKIPPED(reason)]. Состояния регистрировать только по фактическому исполнению.

## Недоступность

Если skill не найден или недоступен после реальной попытки чтения, зафиксировать COPYWRITER_TEST_SKIPPED с точной причиной. Не выдавать обычный текст за исполнение плагина. Три штатных варианта продолжают обычный маршрут; если запрос касается только тестовой версии, коротко сообщить конкретный сбой. Доступность skill не подтверждает доступность внешнего приложения/API.

## Оценка теста

Не назначать копирайтера обязательным автором и не объявлять его победителем заранее. При запросе сравнения оценивать все кандидаты по одной цели: первая строка, конкретика, голос, ясность, соответствие CTA и фактам. Для приглашения в блог — переход к статье; для продажи — обращение. Записывать реальный выбор Leo или доступные метрики с датой и источником. Отсутствующие клики/охваты не заменять предположениями. Не назначать автоматический срок теста или расписание без решения Leo.
