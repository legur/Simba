# AI PLUGIN TOOLS

Версия: 2.0 · 19.10.2026 · технический интеграционный слой
Основание: Leo «Берём» → «В систему симбы на гитахабе».
Канонический код: `integrations/ai_plugins/bridge.py`; установка и команды:
`integrations/ai_plugins/README.md`.

## Назначение и доступность

Xberg извлекает документы; humanizer-ru даёт диагностику текста; BulkPublish принимает
готовый материал как draft. Творческие роли и обязательные gates остаются прежними.
Перед реальным использованием выполнить doctor. Успешная запись кода в GitHub
не означает установку пакетов или авторизацию сервиса.
Не загружать внешний SKILL.md вместо канонического Humanizer, не запускать
автообновление upstream-инструкций и не переносить внешние запреты как закон Simba.
GA4/Clarity, ultramotion и ssot-check пока в shortlist, в этот релиз не входят.

## Source Resolution → Xberg

Для локального PDF/скана/Office-прайса при необходимости структурированного
извлечения применять Xberg внутри SOURCE RESOLUTION, до классификации.
Результат `EXTRACTED_UNVERIFIED` содержит путь и hash исходника, текст и таблицы.
После извлечения сверить коммерческие поля с оригиналом: дата, валюта, единица цены,
размещение, питание, программа, включения и ограничения. Нечитаемую ячейку не
восстанавливать догадкой. XML поставщика сохраняет приоритет в SPA-задачах.
Извлечение не является FACTS_VERIFIED и не разрешает запись в Wix.
При XBERG_UNAVAILABLE использовать имеющийся reader/OCR с теми же проверками;
если источник получить невозможно, SOURCE_BLOCKED. Недоступность инструмента
не является BLOCKED_KB_UNAVAILABLE.

## Финальный текст → humanizer-ru

Применять только в существующей точке финальной обработки готового текста согласно
`Симба (Писатель)/Humanizer-v1.4.md` (внутренняя версия 2.0).
Сначала scan исходника; далее точечная ручная редактура по каноническому модулю;
затем scan чистовика с --before. Для News использовать --genre news.
Отчёт содержит признаки и факт-замок, но не определяет авторство и не заменяет
сверку смысла. Цены, даты, единицы, включения, CTA, контакты, оговорки и голос
сохраняются. Ирония Leo и разрешённая образная гипербола не снимаются ради балла.
Если сканер отсутствует, применить ручной канонический Humanizer; при запросе
автоматической проверки сообщить, что сканер не запускался. Балл не выдумывать.
После смысловой правки результата Simba вернуть его в существующий Internal Critic
repair-loop; после изменения уже утверждённого текста снова получить утверждение.
Ни scan, ни высокий балл не присваивают APPROVED_TEXT.

## PUBLICATION_PACKAGE_READY → BulkPublish draft

Команда «подготовь/передай черновик в BulkPublish» ведёт к PROCESS_OWNER и этому
контракту. До --send проверить реальное APPROVED_TEXT, точный текст, целевой канал
и при наличии визуала FINAL_VISUAL_READY. Само JSON-поле не доказывает согласование.
Предварительный dry-run не требует ключа и не передаёт данные наружу.
Для отправки нужны аккаунт, подключённый канал и секрет BULKPUBLISH_API_KEY.
Результат: BULKPUBLISH_DRAFT_CREATED с provider ID из ответа; проверить созданный
draft в кабинете перед сообщением об успешной передаче. Если read-back недоступен,
указать это явно; не называть публикацией.
Без ключа: BULKPUBLISH_NOT_CONFIGURED, сохранить локальный package и сообщить точную
зависимость. Без final media ID: сначала загрузка через кабинет/проверенный инструмент;
данная версия bridge не загружает файлы. Не терять запрошенный визуал молча.
Автопубликация и schedule не реализованы. Для них нужен отдельный утверждённый процесс.
APPROVED и PUBLISHED в Content Library сохраняют прежний смысл.

## Zernio CLI

По прямой задаче Leo Zernio подключён к существующему PROCESS_OWNER после
PUBLICATION_PACKAGE_READY. Точный контракт: `integrations/ai_plugins/ZERNIO.md`;
адаптер: `integrations/ai_plugins/zernio.py`. Это отдельный провайдер, BulkPublish
не вызывается как fallback и не получает дублирующую отправку.
Перед отправкой нужны реальные утверждения текста/финального визуала и явный выбор
Leo между `Leo's Travel Tips` и `Simba World Travel`; при отсутствии выбора уточнить.
Существующая CLI-авторизация используется без копирования/вывода ключей.
Draft всегда создаётся с --draft, после lookup/блокировки/журнала и загрузки картинки.
Успех подтверждает posts:get со сверкой ID/страницы/exact text/media/status;
PROCESS_OWNER показывает эти поля Leo. Повтор переиспользует ID; UNKNOWN блокирует
повторную запись до сверки. CLI не имеет атомарной межмашинной idempotency — один
исполнитель, без параллельной отправки из разных checkout.
Публикация/расписание только по отдельной явной команде Leo для конкретного ID,
после нового readback; адаптер этих действий не предоставляет. Секреты и журнал
не коммитятся. Новый paid API/подписка не подключаются; используется текущий аккаунт.


## Provenance и проверка релиза

В trace при фактическом использовании сохранять TOOL/версию, SOURCE/hash для
извлечения, scanner report для диагностики и remote draft ID для BulkPublish.
Не сохранять ключи или авторизационные заголовки.
Статус интеграции: код/контракты подготовлены; внешние smoke-тесты фиксируются
отдельно после реального исполнения, не выводятся из offline unit-tests.
После изменения этого workflow обязателен KB_LINT.
