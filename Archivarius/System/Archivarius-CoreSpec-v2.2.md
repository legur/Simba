# Archivarius Core Spec

Версия: v2.2
Дата: 2026-07-13

## Назначение
Archivarius — файловая система для хранения, поиска, нормализации и релизной сборки карточек промтов.

## Принципы
1. Источник истины — md-карточка
2. Индекс — производный слой
3. PROD — только релизный слепок
4. Memory не используется для хранения карточек
5. Семпл опционален
6. Тип карточки влияет на правила валидации
7. Каждая карточка обязательно сохраняется на Drive в папку своей категории — показ в чате не заменяет сохранение
8. Карточка версионируется: AR-ID не меняется, версия увеличивается при изменении содержимого

## Поддерживаемые типы карточек
- prompt
- prompt_pack
- guide
- methodology

## Поддерживаемые статусы
- draft
- active
- needs_fix
- archived
- duplicate

## Правила включения в PROD
В PROD включаются только карточки со статусом `active`.
Карточки с `source`, указывающим на внешний автоимпорт (например, `f/prompts.chat`), или с `routing_confidence` ниже 0.6 — не включаются в PROD по умолчанию до ручной проверки, даже при статусе `active`.

## Обязательные артефакты релиза
- core/CORE_SPEC.md
- index/INDEX.jsonl
- index/INDEX.md
- cards/*.md
- changelog/CHANGELOG.md
- QA_REPORT.md

## Правила именования
- Карточка: AR-YYYYMMDD-XXX_vN.md (N — номер версии, начиная с 1)
- Семпл: 03_SAMPLES/AR-YYYYMMDD-XXX/S01.webp
- QA-отчет: QA_REPORT_YYYYMMDD.md
- PROD: PROD_Archivarius_YYYYMMDD.zip

## Версионирование
- новая карточка → version: v1
- любое изменение содержимого → версия +1, новый файл, старые версии не удаляются
- актуальна версия с максимальным N для данного AR-ID
- предыдущие версии система не удаляет (нет инструмента удаления на Drive) — ручная очистка на стороне пользователя при необходимости
- карточки без поля `version` (созданные до v2.0) считаются `version: v1` по умолчанию; поле проставляется явно только при следующем реальном редактировании конкретной карточки — массовая ретроактивная правка всех файлов не требуется

## Режимы проверки

### ADD-LINT
Проверяет:
- наличие front matter
- наличие id
- наличие title
- наличие type
- наличие status
- наличие содержимого карточки

### RELEASE-STRICT
Проверяет:
- структуру архива
- индекс
- changelog
- уникальность id
- валидность active-карточек
- broken references
- корректность путей к sample

## Источник истины
Главным объектом системы является md-карточка в `cards/`.
Индекс и релиз строятся только на ее основе.
