# Archivarius — протокол нормализации viral prompt-posts


Версия: v1.0  
Дата: 2026-07-18  
Статус: active


---


## 1. Назначение


Протокол применяется к постам из социальных сетей и каналов, где полезный промт окружён заголовком, авторским комментарием, инструкциями по сервисам, эмодзи, призывами подписаться, реакциями, хэштегами и подписью автора.


Цель — извлечь переиспользуемый промт или связанный набор промтов, сохранить исходный текст без искажений и удалить социальную обвязку, не имеющую ценности для повторного применения.


## 2. Типичные зоны входного поста


1. Заголовок или короткая тема.
2. Описание ожидаемого результата.
3. Инструкция по этапам и упоминание сервисов.
4. Один или несколько промтов.
5. Практические наблюдения автора.
6. Призывы подписаться, поставить реакцию или перейти в канал.
7. Хэштеги и подпись.


## 3. Что сохранять


Сохранять:


- полный текст каждого промта без сокращений и улучшений;
- порядок этапов, если промты образуют последовательный процесс;
- обязательные входные данные и переменные;
- полезные замечания о результате и типичных сбоях;
- обязательный референс, формат, режим или техническую платформенную зависимость;
- источник и автора, только если они явно и достоверно указаны либо дана ссылка.


Не сохранять в тело карточки:


- призывы подписаться;
- просьбы поставить реакцию;
- рекламные вставки;
- декоративные эмодзи-маркеры;
- повторяющиеся хэштеги общего вида `#ai`, `#prompt`, `#нейросеть`;
- неподтверждённую подпись как автора источника;
- текст, не влияющий на использование промта.


## 4. Определение типа карточки


- Один самостоятельный промт → `type: prompt`.
- Несколько независимых промтов на одну тему → `type: prompt_pack`.
- Несколько связанных этапов, например изображение → анимация → монтаж → `type: prompt_pack`.
- Пошаговая инструкция с настройкой, диагностикой и несколькими действиями вне самих промтов → `type: guide`.
- Полная система работы с правилами, QA и ветвлением решений → `type: methodology`.


Для связки `text-to-image` + `image-to-video` использовать одну карточку `prompt_pack`, если второй промт зависит от результата первого.


## 5. Категория и формат


Категория определяется по конечному результату:


- итоговое изображение → `01_Изображения`;
- итоговое видео → `02_Видео_и_анимация`;
- итоговый текст → `03_Тексты_и_копирайтинг`;
- код, приложение или интерфейс → программирование и цифровые продукты.


Для двухэтапной связки «изображение → видео» основная категория — видео, даже если первый этап создаёт статичный кадр.


Формат выбирается из канонического списка. Для image-to-video набора использовать `format: video_prompt` и перечислить режимы:


```yaml
mode:
  - text-to-image
  - image-to-video
```


## 6. Правило платформы


Поле `platform` добавляется только при технической зависимости:


- фирменный синтаксис;
- специальные параметры;
- уникальная функция интерфейса;
- обязательная модель или API;
- невозможность переноса без адаптации.


Если пост просто рекомендует GPT Image, Kling, Midjourney, Gemini, Grok, Wan или другой сервис, но промт написан обычным естественным языком, `platform` не добавляется. Рекомендуемые или протестированные сервисы перечисляются в `## Примечания`.


## 7. Перевод


Если промт полностью или частично не на русском языке, сохранять рядом:


```markdown
## Промпт N — оригинал
```text
Полный исходный текст.
```


## Промпт N — перевод на русский
```text
Полная русская версия.
```
```


Правила:


- оригинал не редактировать;
- перевод не заменяет оригинал;
- смешанный промт переводить целиком в полноценную русскую версию;
- команды, параметры, переменные, плейсхолдеры, имена моделей и код не переводить, если это нарушает работу;
- каждый нерусский промт в `prompt_pack` получает собственный перевод непосредственно рядом.


## 8. Переменные и референсы


Извлекать переменные из конструкций:


- `[ПЕРСОНАЖ]`;
- `{PRODUCT}`;
- `<CITY>`;
- `YOUR_NAME`;
- явных указаний «вставьте имя», «замените объект», «добавьте фото».


`reference_required: true` ставится только тогда, когда без референса промт не выполняет заявленную задачу. Если фото или изображение лишь улучшает результат, использовать `reference_required: false` и отметить опциональный референс в инструкции.


## 9. Название и теги


Название должно быть функциональным, конкретным и пригодным для поиска. Из эмоционального заголовка формируется нормальное название результата, но узнаваемая тема сохраняется.


Теги:


- от 3 до 7;
- lowercase;
- без дублей;
- описывают результат, жанр, режим и ключевой сценарий;
- общие хэштеги исходного поста не копируются механически.


## 10. Каноническая структура viral prompt-card


```markdown
## Пост
Короткое описание результата.


## Назначение
Главный сценарий применения.


## Инструкция
Порядок использования, переменные и референсы.


## Промпт 1 — оригинал
```text
...
```


## Промпт 1 — перевод на русский
```text
...
```


## Промпт 2 — оригинал
```text
...
```


## Промпт 2 — перевод на русский
```text
...
```


## Примечания
Платформы тестирования, практические наблюдения, ограничения и удалённая социальная обвязка.
```


Блоки перевода создаются только для нерусских или смешанных промтов.


## 11. Обработка наблюдений автора


Фразы вроде «в этой модели выглядит логичнее», «иногда появляются артефакты» или «стиль повышает детализацию» сохраняются как наблюдения источника, а не как универсальные факты.


Формулировка:


> По наблюдениям автора исходного поста...


Не превращать субъективный опыт автора в системное утверждение без отдельной проверки.


## 12. ADD-LINT для viral prompt-posts


Проверить:


- социальная обвязка отделена от полезного содержимого;
- все исходные промты сохранены полностью;
- порядок связанных этапов сохранён;
- тип карточки соответствует структуре материала;
- категория выбрана по конечному результату;
- `platform` добавлена только при технической зависимости;
- все нерусские и смешанные промты имеют русский перевод;
- переменные перечислены;
- обязательность референса определена корректно;
- тегов от 3 до 7;
- карточка сохранена в одной финальной папке;
- индекс папки обновлён.


## 13. Короткая формула


```text
сырой социальный пост
→ отделить промты от обвязки
→ определить один или несколько связанных этапов
→ сохранить оригиналы без изменений
→ добавить русские переводы
→ определить конечный результат и категорию
→ не указывать платформу без технической зависимости
→ извлечь переменные и референсы
→ создать карточку
→ ADD-LINT
```
