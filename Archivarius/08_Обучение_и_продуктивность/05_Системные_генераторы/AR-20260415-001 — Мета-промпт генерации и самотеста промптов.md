## Назначение
Мета-промпт для генерации рабочих промптов под регулярные задачи. Сначала модель пишет самодостаточный шаблон промпта, затем сразу тестирует его на примере, находит слабые места и при необходимости выпускает улучшенную версию v2.

## Когда использовать
Подходит для:
- повторяющихся рабочих задач
- создания шаблонов промптов под конкретный процесс
- упаковки лучших практик в один reusable prompt
- проверки качества промпта до реального использования
- построения собственной библиотеки промптов

## Исходный промпт
```text
Я хочу: [описание задачи которую буду делать регулярно]

Напиши для меня промпт-шаблон:
1. Роль для Claude (кто он в этой задаче)
2. Чёткий формат вывода
3. Ограничения (чего НЕ делать)
4. Один заполненный пример использования

Промпт должен быть самодостаточным — копирую и использую.

Шаг 2 — Тест:
Протестируй промпт который ты написал.
Выполни его с примером.
Если результат не идеален — улучши и покажи v2.
```

## S01 — семпл использования
```text
Я хочу: каждую неделю превращать сырой список новостей туризма в короткий, понятный и полезный Facebook-пост для аудитории 45+ из Израиля.

Напиши для меня промпт-шаблон:
1. Роль для Claude (кто он в этой задаче)
2. Чёткий формат вывода
3. Ограничения (чего НЕ делать)
4. Один заполненный пример использования

Промпт должен быть самодостаточным — копирую и использую.

Шаг 2 — Тест:
```

## Практические заметки
Сильные стороны:
- превращает разовый запрос в воспроизводимый инструмент
- добавляет обязательную проверку, а не оставляет промпт на уровне теории
- помогает находить дыры в формате, ограничениях и примерах
- особенно полезен для регулярных задач, где важна стабильность результата

Риски:
- модель может написать слишком общий промпт без учета контекста ниши
- тест иногда бывает слишком мягким и не выявляет реальные слабые места
- если исходная задача описана расплывчато, на выходе получится расплывчатый шаблон
- формулировка с упором на Claude может излишне привязывать промпт к одной модели

Рекомендации:
- лучше описывать задачу не абстрактно, а через вход, выход и критерий качества
- полезно заранее указывать аудиторию, стиль, длину и запреты
- для рабочих задач стоит просить не только v2, но и список исправлений между v1 и v2
- для кросс-модельного использования лучше заменить "роль для Claude" на "роль для модели"

## Fix note
Главная сила этого мета-промпта — шаг тестирования. Без него шаблон легко выглядит умным, но ломается в реальной работе.

Главная слабость — он пока не заставляет модель:
- назвать критерии успеха заранее
- сравнить v1 и v2 явно
- объяснить, что именно было исправлено

Рабочая трактовка:
использовать этот промпт как генератор первичной рабочей версии, а для важных задач добавлять явный блок критериев качества и post-mortem после теста.

## Мини-усиления
Если нужен более строгий режим проверки:
```text
После теста перечисли 3 слабых места промпта, затем исправь их и покажи улучшенную версию v2 с кратким списком изменений.
```

Если нужен универсальный вариант не только для Claude:
```text
Замени упоминание Claude на нейтральное "модель" и делай промпт совместимым с ChatGPT, Claude и другими LLM.
```

Если нужен более прикладной результат:
```text
Перед написанием промпта сначала сформулируй: входные данные, желаемый выход и критерии хорошего результата.
```
