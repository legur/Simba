## Назначение
Мета-промпт, который заставляет модель сначала ответить, затем разложить ответ на факты, проверить каждый факт и только после этого выдать финальную версию с пометками о том, что подтверждено, исправлено или осталось непроверенным.

## Когда использовать
Подходит для:
- ответов, где важна фактическая точность
- снижения галлюцинаций
- проверки чернового ответа перед отправкой
- сложных объяснений, аналитики и резюме
- работы в режиме "сначала ответь, потом проверь себя"

## Исходный промпт
```text
[Твой вопрос / задача]

Прежде чем дать финальный ответ:

1. Ответь на вопрос (черновик)
2. Составь список всех фактов из черновика
3. Проверь каждый: верен ↔ неверен ↔ не уверен
4. Для "не уверен" — скорректируй
5. Финальный ответ с пометками:
   ✅ проверено
   ⚠️ скорректировано (было → стало)
   ❓ не удалось проверить
```

## S01 — семпл использования
```text
Сколько часов лететь из Тель-Авива в Бангкок?

3. Проверь каждый: верен ↔ неверен ↔ не уверен
4. Для "не уверен" — скорректируй
5. Финальный ответ с пометками:
   ✅ проверено
   ⚠️ скорректировано (было → стало)
   ❓ не удалось проверить
```

## Практические заметки
Сильные стороны:
- заставляет модель сделать второй проход по собственному ответу
- помогает отделить уверенные факты от сомнительных
- полезен для ответов с большим количеством конкретики
- делает неопределенность видимой, а не скрытой

Риски:
- модель может "проверять" саму себя без реальной внешней верификации
- на слабых моделях блок проверки иногда выглядит убедительно, но не добавляет реальной точности
- формат удлиняет ответ
- не решает проблему отсутствия доступа к источникам

Рекомендации:
- лучше всего работает вместе с явным требованием использовать источники
- особенно полезен там, где легко спутать даты, цифры, имена и причинно-следственные связи
- для рабочих задач можно просить показывать только финальный блок, а черновик и проверку скрывать
- для коротких бытовых запросов обычно избыточен

## Fix note
Главная сила промта — в разделении двух режимов:
сначала быстрый черновик,
потом медленная проверка по фактам.

Главная слабость — шаг "проверь каждый факт" не указывает, ЧЕМ именно проверять.
Без этого модель может просто сделать внутреннюю переоценку уверенности, а не реальную верификацию.

Рабочая трактовка:
использовать как каркас самопроверки,
а для реальной надежности добавлять явный источник проверки: документы, ссылки, база знаний, веб-поиск, таблица, прикрепленный файл.

## Мини-усиления
Если нужна более строгая проверка:
```text
Для каждого факта укажи, на чем основана проверка: память модели, приложенный источник, документ, веб-источник или вывод по логике.
```

Если нужен более компактный вывод:
```text
Не показывай черновик и полный список фактов, а выведи только финальный ответ и список исправленных или непроверенных утверждений.
```

Если нужен режим для работы с источниками:
```text
Не считай факт проверенным, если у него нет явного основания: источник, цитата, документ или надежная ссылка.
```
