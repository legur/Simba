# AR-METHOD — Pattern Extraction for Travel Content
Короткий модуль Archivarius о том, как разбирать сильные тексты на рабочие механики и превращать их в свои посты без копирования.

> [!NOTE]
> Карточка предназначена для Jarvis / Critic / Humanizer / ручного анализа референсов.  
> Использовать как методологию, а не как шаблон-копипаст.

## Назначение
Модуль нужен для извлечения **паттернов из сильных текстов** с последующей адаптацией под:
<br/>Facebook
<br/>WhatsApp
<br/>сайт
<br/>оперативные посты
<br/>экспертные посты
<br/>продающие посты
<br/>личные тексты
<br/>Threads

Главная задача:
<br/>не копировать чужой текст,
<br/>а понять, **за счет чего он работает**,
<br/>и перенести эти механики в свой контент.

## Связанные модули
| Модуль | Роль |
|---|---|
| Jarvis | определяет тип задачи и запускает нужный режим анализа |
| Critic 2.0 | проверяет, насколько корректно извлечены механики и не потеряна цель текста |
| Humanizer-pass v1.0 | убирает стерильность и AI-маркеры после адаптации |
| Segmentation and Brief | помогает привязать паттерн к конкретному сегменту аудитории |
| Simba / Leona / Leo | используют извлеченные механики для генерации нового текста |
| Archivarius | хранит карточку как методологический модуль |

## Входные параметры (payload)
| Поле | Тип | Обязательно | Описание |
|---|---|---:|---|
| source_text | string | да | Исходный сильный текст или фрагмент |
| source_type | string | нет | Тип источника: post / ad / thread / article / email / comment |
| platform | string | нет | Платформа источника: Facebook / Threads / site / WhatsApp / other |
| target_platform | string | да | Куда будет адаптирован результат |
| target_goal | string | да | Цель: reach / engagement / trust / save / lead / sale |
| audience_segment | string | да | Сегмент аудитории |
| niche | string | да | Ниша, обычно travel |
| format_type | string | да | Тип текста: selling / expert / personal / operational / news |
| tone | string | нет | Желаемый тон результата |
| constraints | list[string] | нет | Ограничения по длине, стилю, CTA, бренду |
| extract_depth | string | нет | lite / standard / deep |
| output_mode | string | нет | analysis / template / rewritten_post / mixed |

## Выход
Модуль должен выдавать результат в 4 слоя:

1. **Разбор механики**
2. **Список извлеченных паттернов**
3. **Что переносимо / что непереносимо**
4. **Новый каркас под нашу задачу**

Опционально:
<br/>черновик нового поста
<br/>варианты хуков
<br/>усиления по сегменту
<br/>замечания Critic / Humanizer

## Алгоритм

### Step 1. Base Analysis
Сначала текст разбирается **не по теме, а по конструкции**.

Нужно определить:

<br/>1. Чем цепляет первая строка
<br/>2. Какое обещание дается читателю
<br/>3. Где скрытый конфликт или напряжение
<br/>4. За счет чего удерживается внимание
<br/>5. Какой тип пользы дает текст
<br/>6. Как устроен ритм
<br/>7. Какой тип финала используется
<br/>8. Какое действие провоцируется

> [!IMPORTANT]
> На этом этапе запрещено пересказывать текст общими словами вроде:
> <br/>"интересно написано"
> <br/>"хорошо удерживает"
> <br/>"цепляет своей подачей"
>
> Нужна причинно-следственная конкретика.

### Step 2. Pattern Extraction
После анализа извлекаются именно **паттерны**, а не формулировки.

Типовые паттерны:
<br/>цифра в начале
<br/>слом ожиданий
<br/>ошибка аудитории
<br/>контраст "кажется / на деле"
<br/>мини-конфликт
<br/>бытовая деталь
<br/>разрушение мифа
<br/>обещание ясности
<br/>список
<br/>личный опыт
<br/>вопрос в финале
<br/>мягкий CTA
<br/>снятие тревоги

### Step 3. Transfer Filter
Нужно разделить материал на две группы.

**Переносимо:**
<br/>структура
<br/>логика
<br/>ритм
<br/>тип крючка
<br/>тип напряжения
<br/>тип пользы
<br/>тип финала
<br/>способ CTA

**Непереносимо:**
<br/>чужие цифры
<br/>чужой контекст
<br/>чужая история
<br/>чужие формулировки
<br/>чужой тон, если он не совпадает с брендом
<br/>слова-маркеры, по которым будет ощущаться копирование

> [!WARNING]
> Если в результате адаптации узнается исходный текст, значит модуль сработал неправильно.
> Цель - перенос механики, а не маскировка копии.

### Step 4. Audience Binding
После извлечения паттернов они привязываются к нашей аудитории.

Нужно определить:
<br/>что болит у сегмента
<br/>что ему непонятно
<br/>чего он боится
<br/>что мешает действию
<br/>какой уровень доверия у аудитории
<br/>на каком этапе воронки находится читатель

Для travel это особенно важно.

Типовые оси:
<br/>мечта + страх
<br/>впечатление + понятность
<br/>красота + логистика
<br/>интерес + риск ошибки
<br/>желание отдохнуть + тревога из-за неопределенности

### Step 5. Template Build
На основе связки "паттерн + аудитория + цель" собирается новый каркас.

Каркас обычно включает:
<br/>хук
<br/>смысловое обещание
<br/>основную логику
<br/>выгоду или пользу
<br/>снятие тревоги
<br/>финал
<br/>CTA

Для разных целей каркас меняется:

| Цель | На чем фокус |
|---|---|
| Reach | сильный хук, контраст, простая считываемость |
| Engagement | вопрос, поляризация, узнавание |
| Trust | ясность, факты, опыт, отсутствие нажима |
| Save | практичность, чек-лист, польза |
| Lead | проблема + понятное решение |
| Sale | желание + снятие риска + конкретный следующий шаг |

### Step 6. Humanizer Pass
Перед финалом текст проходит проверку на:
<br/>стерильность
<br/>канцелярит
<br/>абстракции
<br/>отсутствие фактуры
<br/>слишком ровный нейроритм
<br/>отсутствие человеческой интонации

Исправления:
<br/>заменить общие слова на детали
<br/>убрать шаблоны
<br/>сделать фразы короче и живее
<br/>оставить одну смысловую ось
<br/>проверить, что польза считывается быстро

## Практический формат разбора
Рекомендуемый формат вывода при анализе одного текста:

### 1. Что цепляет
Краткое описание хука и почему он работает.

### 2. Что обещает
Какой результат или смысл обещан читателю.

### 3. Что удерживает
Какие элементы не дают выпасть из текста.

### 4. Главный триггер
Эмоция, на которой держится текст.

### 5. Тип пользы
Что получает читатель:
<br/>эмоцию
<br/>ясность
<br/>экономию
<br/>предостережение
<br/>решение
<br/>облегчение

### 6. Тип финала
Вывод / вопрос / приглашение / CTA / открытая петля.

### 7. Что можно взять себе
Только переносимые механики.

### 8. Что нельзя переносить
Все, что привязано к чужому контексту.

### 9. Как адаптировать под нашу аудиторию
Связка с сегментом, целью и платформой.

## QA Checklist
- [ ] Хук разобран конкретно, а не общими словами
- [ ] Определен тип обещания

- [ ] Показано, что удерживает внимание
- [ ] Выделены переносимые паттерны
- [ ] Отделены непереносимые элементы
- [ ] Есть привязка к аудитории
- [ ] Есть привязка к цели поста
- [ ] Новый каркас не копирует исходник
- [ ] После адаптации текст звучит по-человечески
- [ ] Нет AI-штампов и пустых формул
- [ ] Польза считывается за несколько секунд

## Fix Pack

### Fix 1. Слишком общий разбор
**Проблема:** анализ выглядит как набор оценок без механики.

```text
Плохо:
"Текст интересный, живой и хорошо держит внимание"

Нормально:
"Текст цепляет с первой строки за счет контраста между ожиданием и реальностью. Дальше удерживает обещанием конкретной пользы и короткими смысловыми блоками"
```

### Fix 2. Копирование темы вместо механики
**Проблема:** при адаптации переносится чужой контекст.

```text
Плохо:
берем тему, сюжет и формулировки источника

Нормально:
берем только тип хука, тип напряжения, ритм и способ финала
```

### Fix 3. Нет привязки к цели
**Проблема:** текст получается "интересным", но неясно зачем он написан.

```text
Перед сборкой нового каркаса обязательно указать:
цель поста
сегмент
уровень теплоты аудитории
целевое действие
```

### Fix 4. Стерильный результат
**Проблема:** после адаптации текст звучит слишком гладко.

```text
Что делать:
убрать универсальные фразы
добавить конкретную тревогу или деталь
сократить лишние связки
заменить абстракции на бытовую пользу
```

## Правило стопа
> [!CAUTION]
> Если после разбора нельзя ответить на вопрос:
> <br/>"какой именно прием сработал, на какую эмоцию, для какой аудитории и почему",
> значит анализ нужно делать заново.

Также остановить генерацию и пересобрать вывод, если:
<br/>результат слишком похож на оригинал
<br/>цель поста не определена
<br/>непонятно, какая польза у текста
<br/>разбор состоит из вкусовых оценок вместо причин

## Применение в travel-нише
Для тревел-контента модуль особенно полезен в 3 случаях:

### 1. Разбор сильных референсов
Когда есть хороший пост конкурента, блогера или медиа, и нужно понять, что в нем реально работает.

### 2. Усиление продающих постов
Когда текст выглядит "нормально", но не хватает:
<br/>крючка
<br/>снятия тревоги
<br/>ритма
<br/>внятной пользы
<br/>мягкой конверсии

### 3. Адаптация контента под сегменты
Один и тот же паттерн может звучать по-разному:

<br/>для эконом-сегмента - ясность, выгода, отсутствие путаницы
<br/>для comfort - спокойствие, продуманность, предсказуемость
<br/>для premium - качество, приватность, точность
<br/>для expert-контента - объяснение, контекст, доверие

## Рекомендуемый промпт запуска
```text
Разбери этот текст не по теме, а по механике.
Определи:
1) чем цепляет первая строка,
2) какое обещание дается,
3) где напряжение,
4) что удерживает внимание,
5) какой тип пользы получает читатель,
6) как устроен ритм,
7) какой тип финала,
8) какие паттерны можно перенести в travel-нишу.

После этого отдели переносимое от непереносимого
и собери новый каркас поста для [платформа] под цель [цель] и сегмент [сегмент].
В финале проверь результат на стерильность и AI-маркеры.
```
