## Пост


Системный навык для извлечения отдельных предметов одежды из фотографий, где одежда надета на человеке. Процесс инвентаризирует уникальные изделия, реконструирует их по видимым данным, удаляет однотонный фон и выдаёт только проверенные прозрачные RGBA PNG.


## Назначение


Методология предназначена для пакетной подготовки каталожных изображений одежды из фотографий образов или моделей. Она охватывает поиск и нормализацию исходников, идентификацию предметов, создание референсов, evidence-bound генерацию, удаление хромакея, технический и визуальный QA, консервативную дедупликацию и финальную выдачу.


## Структура


1. Получение входного пути и имени новой папки результата.
2. Поиск и нормализация фотографий без изменения оригиналов.
3. Инвентаризация всех различимых предметов одежды.
4. Создание внутреннего манифеста и сфокусированных кропов.
5. Формирование промта Imagegen, ограниченного видимыми свидетельствами.
6. Генерация отдельных предметов на однотонном хромакее.
7. Преобразование результата в прозрачный RGBA PNG.
8. Технический и визуальный контроль качества.
9. Консервативная дедупликация по исходным фотографиям.
10. Выдача только принятых PNG без временных материалов.

````markdown
# Extract Clothing Cutouts


Turn photographs of worn clothing into source-faithful standalone catalog PNGs. Treat each result as a reconstruction from visible evidence, not literal segmentation whenever the wearer or another layer occludes part of the garment.


## Start by asking for two paths


Before doing any work, obtain both values unless the user already supplied them:


1. Ask: `Where can I find the input images? You can give me "." or a folder path relative to the current directory.`
2. Ask: `What should the new output folder be called? I will create it inside the current directory.`


Resolve a relative input path from the current working directory. Resolve the output as exactly one new child folder of the current working directory. If the output path already exists, ask for a different folder name. Do not merge with or overwrite an existing folder.


## Output contract


- Put only finished transparent RGBA clothing PNGs in the requested output folder.
- Use descriptive lowercase hyphenated names such as `navy-fair-isle-cardigan.png`.
- Keep source copies, crops, prompts, chroma images, manifests, and QA files in temporary storage only.
- Preserve every input image unchanged.
- Delete temporary work after final verification succeeds.
- Return the absolute output path and number of PNGs created. Briefly mention clothing fragments skipped because they were too obscured.


Create temporary work outside the output folder:


```bash
WORK="$(mktemp -d "${TMPDIR:-/tmp}/clothing-cutouts.XXXXXX")"
mkdir -p "$WORK"/{source-jpg,crops,chroma,items,qa}
```


If a deterministic helper is needed, write it under `$WORK`; never add auxiliary files to this skill or the final output folder.


## Non-negotiable quality rules


- Read and follow the built-in `imagegen` skill before the first image generation or edit.
- Generate exactly one item per output, except an established matching pair such as shoes or socks.
- Exclude the wearer, body, skin, hair, mannequin, hanger, props, other layers, and scene.
- Prefer omission over invention. Do not guess unreadable text, hidden construction, branding, pockets, fasteners, hardware, or trim.
- Hold fragments whose item type or defining construction cannot be recovered without substantial fabrication.
- Merge duplicates only when source photographs support physical identity. Generated-image similarity is not proof.
- Inspect source crops and final contact sheets visually. Numeric alpha checks cannot establish source fidelity.


## Workflow


### 1. Discover and normalize the source photos


Use `rg --files` first. Include common raster formats such as JPEG, PNG, WebP, HEIC/HEIF, TIFF, BMP, and AVIF. Exclude the requested output path and temporary work path from discovery.


Create upright high-quality JPEG working copies in `$WORK/source-jpg`:


- Apply EXIF orientation.
- Preserve the original pixel dimensions unless memory pressure requires downscaling; never upscale.
- Convert only the working copy to RGB JPEG at quality 95 or better.
- Resolve duplicate basenames with a short stable hash of the relative source path.
- Record original path, normalized filename, dimensions, and source hash in `$WORK/sources.json`.
- Use Pillow when it can decode the format; use `sips` on macOS or `ffmpeg` as a HEIC/AVIF fallback.


Create source contact sheets of at most 12 images each, labeled with normalized filenames. Open and inspect every sheet. Do not infer the wardrobe from filenames alone.


For large folders, split a read-only inventory among subagents using disjoint source batches. Keep one main agent responsible for global item identity, duplicate decisions, generation reconciliation, and final QA.


### 2. Inventory every deliberately worn item


Include tops, bottoms, outerwear, dresses, footwear, hosiery, swimwear, belts, ties, and headwear. Exclude non-clothing props unless requested.


Build this internal manifest shape in `$WORK/manifest.json`:


```json
{
  "items": [
    {
      "slug": "navy-fair-isle-cardigan",
      "label": "Navy Fair Isle Cardigan",
      "category": "outerwear",
      "status": "generate",
      "confidence": "high",
      "description": "Deep navy long zip cardigan with a white Fair Isle yoke and dotted lower knit.",
      "observed": {
        "color": "deep navy and white",
        "material": "medium-weight knit",
        "silhouette": "long relaxed straight body",
        "construction": "center zipper, long sleeves, ribbed cuffs and hem",
        "marks": "white geometric yoke and small white knit dots"
      },
      "unknowns": [],
      "graphic_policy": "exact",
      "chroma_key": "#00ff00",
      "source_refs": [
        {
          "source": "IMG_1284.jpg",
          "bbox": [0.12, 0.08, 0.83, 0.86],
          "role": "primary",
          "notes": "Best overall silhouette and front construction."
        },
        {
          "source": "IMG_1289.jpg",
          "bbox": [0.18, 0.05, 0.79, 0.91],
          "role": "complementary",
          "notes": "Shows lower length and hem."
        }
      ],
      "possible_duplicates": [],
      "duplicate_evidence": "No matching construction found elsewhere."
    }
  ]
}
```


Use these manifest rules:


- Use unique lowercase hyphenated slugs.
- Express bounding boxes as normalized `[left, top, right, bottom]` floats in `[0, 1]` on the upright normalized source.
- Make the first reference the strongest overall view.
- Add at most one complementary reference unless an exceptional item genuinely needs more.
- Use `graphic_policy: exact` only for legible wording, `mark-only` for a visible but unreadable emblem, and `omit` for uncertain branding.
- Put uncertain attributes in `unknowns`; do not convert guesses into facts.
- Use `status: hold` when item type or defining construction is unknowable.
- Consolidate source-proven repeats before generation, but keep visually similar items separate when identity is uncertain.


### 3. Prepare focused generation references


For every `generate` record:


1. Convert the normalized bounding box to pixels.
2. Add about 12% padding on every side, clamped to the image bounds.
3. Reject a crop whose shorter original dimension is below about 64 pixels unless the item is legitimately narrow, such as a belt or tie.
4. Preserve aspect ratio and place the crop on a neutral square canvas around 1200–1400 pixels.
5. Save the primary crop as `$WORK/crops/SLUG.jpg` and a complementary crop as `SLUG-ref2.jpg`.


Create labeled crop contact sheets and inspect them. Keep enough context to distinguish the target from underlayers while making the target dominant. Never combine references merely because the garments look similar.


### 4. Build one evidence-bound Imagegen prompt per item


Use this structure, replacing every bracket with source evidence and deleting irrelevant clauses:


```text
Use case: background-extraction
Asset type: transparent ecommerce clothing catalog cutout, generated first on a removable chroma key
Input image(s): The reference photograph(s) show the exact same [ITEM] worn by a person. Use them only to identify and reconstruct that item. Image 1 contributes [SILHOUETTE/CONSTRUCTION]. Image 2 contributes [DETAIL], if present. Do not mix in details from visually similar clothing.
Primary request: Reconstruct ONLY the complete empty [ITEM NAME] as a clean [FRONT/ANGLE] ecommerce catalog product photograph. Remove the wearer, body, skin, hair, [VISIBLE UNDERLAYER], [OTHER CLOTHING], and the scene. Show the complete unoccluded item, naturally and symmetrically arranged, with no person, mannequin, or hanger visible.
Item fidelity: Preserve the source-supported [COLOR], [MATERIAL/TEXTURE], [SILHOUETTE], [NECKLINE/WAIST/OPENING], [SLEEVES/LEGS/SHAFTS], [FASTENING], [HEM/SOLE], [PATTERN], and [CLEAR MARKS]. [STATE UNKNOWNS AND WHAT TO OMIT.] Do not invent any other logo, lettering, label, pocket, seam, fastener, hardware, color, or decoration.
Composition: [SQUARE/PORTRAIT/LANDSCAPE] canvas, centered [VIEW], complete item fully inside frame with generous even padding around every outer edge; no cropping or truncation.


Background: perfectly flat, absolutely uniform solid [CHROMA KEY] edge-to-edge. The background must be exactly one color with no shadow, gradient, texture, vignette, floor, horizon, reflection, or lighting variation.
Lighting: neutral diffuse high-end ecommerce product lighting contained on the item only; no cast shadow, contact shadow, reflection, prop, watermark, caption, or border.


Critical: use no [CHROMA KEY] anywhere in the item; preserve a crisp separable outer silhouette; output only one [ITEM OR MATCHED PAIR].
```


Use direct evidence language:


- `Preserve the four small white buttons visible in a vertical row.`
- `The pink fabric is a separate underlayer and must not appear.`
- `The dark lower shapes are cast leaf shadows, not a print.`
- `The source mark is unreadable; omit text rather than inventing it.`
- `The neckline is unresolved; use the simplest construction consistent with the visible opening.`


Avoid vague requests such as `make it stylish`, `improve the design`, or `complete it naturally`; they encourage invention.


Choose the chroma key:


- Default to pure `#00ff00`.
- Use `#ff00ff` for green garments unless magenta or pink is prominent.
- Otherwise choose a maximally distant pure saturated RGB color and record it as `chroma_key`.
- Require the same solid color at every border pixel.


Choose category-appropriate framing:


- Tops and outerwear: front view with neck opening, complete sleeves, cuffs, and hem.
- Pants and tights: portrait view with waistband, full legs, and complete hems or enclosed feet.
- Skirts and dresses: front view with waistband or neckline, full length, and complete hem.
- Footwear: a matched pair only when established; use a slightly elevated front three-quarter view when openings and soles matter.
- Belts and ties: align the long axis with a landscape or portrait canvas and keep both ends complete.
- Swimwear: complete every strap and tie endpoint.


### 5. Generate and reconcile


Use the built-in Imagegen tool with the primary crop and only a genuinely complementary second crop. Save the returned chroma image to `$WORK/chroma/SLUG.png` and keep the exact prompt in temporary records.


For more than eight items, partition disjoint slug batches among subagents. Limit each slug to one active generation. Require each worker to return slug, prompt, reference paths, chroma path, and brief visual review. Reconcile all results against the manifest and resume only missing or failed slugs.


Compare every chroma result with its source before accepting it. Plausibility alone is insufficient.


### 6. Remove the chroma background


Prefer the tested helper from the built-in Imagegen skill when present:


```bash
python3 "${CODEX_HOME:-$HOME/.codex}/skills/.system/imagegen/scripts/remove_chroma_key.py" \
  --input "$WORK/chroma/SLUG.png" \
  --out "$WORK/items/SLUG.png" \
  --auto-key border \
  --soft-matte \
  --transparent-threshold 12 \
  --opaque-threshold 220 \
  --despill \
  --force
```


If that helper is unavailable, implement the same temporary operation with Pillow:


1. Sample the median RGB value from a thin band around all four borders.
2. For each pixel, measure maximum per-channel distance from the sampled key.
3. Make distance `<=12` fully transparent and distance `>=220` fully opaque.
4. Use a smoothstep alpha ramp between those thresholds and multiply by the original alpha.
5. For partially transparent pixels, cap key-dominant channels to the strongest non-key channel to remove spill.
6. Set fully transparent pixels to `(0, 0, 0, 0)` and save RGBA PNG.


Use border sampling only when the generated background is visibly uniform. If removal damages clothing colors, regenerate with a more distant key instead of forcing a destructive matte.


### 7. Perform technical and visual QA


For every PNG, verify with Pillow or an equivalent decoder:


- format is PNG and mode is RGBA;
- alpha channel contains both transparent and visible pixels;
- all four corners are transparent;
- the outer border is substantially transparent;
- nontransparent content is neither empty nor nearly the entire canvas;
- the alpha bounding box leaves visible padding and no item extremity is clipped;
- no obvious chroma-colored pixels remain along partially transparent edges;
- every `generate` manifest slug has exactly one output and no unexplained output exists.


Create checkerboard contact sheets of at most 12 cutouts each in `$WORK/qa`. Inspect every sheet, then inspect sensitive items individually against their source crops.


Apply this visual rubric:


1. Confirm target identity and category.
2. Compare proportions, silhouette, color, and material character.
3. Compare neckline, rise, waist, opening, sleeve or leg length, hem, and sole shape.
4. Compare fasteners, pockets, trim, pattern placement, and clearly legible marks.
5. Confirm complete topology: every sleeve, cuff, strap, tie, hem, toe, heel, shaft, or enclosed foot.
6. Confirm absence of body parts, underlayers, adjacent clothing, props, shadow, and background.
7. Reject unsupported construction or fake text.


Treat failures as:


- Critical: wrong item, body remains, another garment is fused in, major clipping, opaque background, or destructive matte. Regenerate.
- Major: invented hood, collar, pocket, fastening, wrong silhouette or color, fake logo/text, missing defining pattern, or incomplete endpoints. Correct or regenerate.
- Minor: faint edge halo, slight centering drift, or low-impact texture drift. Correct when visible at catalog size.


When correcting, attach the current output plus the strongest source crop and use:


```text
Correct the attached catalog cutout using the source crop. Keep the successful silhouette, color, and chroma-workflow composition. Remove the unsupported [FAILURE]. Restore the source-supported [DETAIL]. Do not add [COMMON HALLUCINATION]. Return the corrected item on the same uniform [CHROMA KEY] background with no shadow.
```


If an item fails twice, rewrite the prompt around the observed failure rather than repeating it unchanged.


### 8. Deduplicate conservatively


Use perceptual hashes or silhouette/color similarity only to rank pairs for review. Never auto-delete from generated-image similarity.


Confirm identity from source photos using matching distinctive construction, pattern placement, distressing, hardware, or logos; compatible color and material; and absence of contradictory details. Repeated outfit context or adjacent-photo chronology is supporting evidence, not sole proof.


Do not merge generic black skirts, plain tops, jeans, or shoes merely because Imagegen standardized their poses. Retain both when source evidence is inconclusive. Keep one canonical slug only for source-proven duplicates.


### 9. Deliver only the finished PNGs


After all accepted items pass:


1. Confirm the requested output folder still does not exist.
2. Create that one folder inside the current working directory.
3. Copy only accepted canonical `.png` files from `$WORK/items` into it.
4. Reopen every copied file and confirm RGBA plus transparency.
5. Confirm the folder contains no non-PNG files, duplicate aliases, or auxiliary artifacts.
6. Delete `$WORK` only after final verification succeeds.


Return the absolute output-folder path and PNG count, and display up to 12 images to the user in chat, mentioning that they can view the rest in the directory. Mention any unrecoverable fragments briefly.
````

````markdown
# Извлечение вырезок одежды


Преобразуй фотографии одежды на человеке в самостоятельные каталожные PNG, максимально соответствующие исходнику. Если человек или другой слой закрывает часть изделия, рассматривай результат как реконструкцию по видимым свидетельствам, а не как буквальную сегментацию.


## Сначала запроси два пути


До начала работы получи оба значения, если пользователь ещё их не указал:


1. Спроси: `Где находятся исходные изображения? Можно указать "." или путь к папке относительно текущей директории.`
2. Спроси: `Как назвать новую папку с результатами? Я создам её внутри текущей директории.`


Разрешай относительный входной путь от текущей рабочей директории. Папка результата должна быть ровно одной новой дочерней папкой текущей рабочей директории. Если путь результата уже существует, попроси другое имя папки. Не объединяй содержимое с существующей папкой и ничего в ней не перезаписывай.


## Контракт результата


- Помещай в запрошенную папку только готовые прозрачные RGBA PNG с одеждой.
- Используй описательные имена в нижнем регистре через дефисы, например `navy-fair-isle-cardigan.png`.
- Исходные копии, кропы, промты, изображения на хромакее, манифесты и QA-файлы храни только во временном хранилище.
- Сохраняй каждое входное изображение без изменений.
- Удаляй временные материалы после успешной финальной проверки.
- Верни абсолютный путь к папке результата и количество созданных PNG. Кратко упомяни фрагменты одежды, которые пришлось пропустить из-за слишком сильного перекрытия.


Создай временную рабочую область вне папки результата:


```bash
WORK="$(mktemp -d "${TMPDIR:-/tmp}/clothing-cutouts.XXXXXX")"
mkdir -p "$WORK"/{source-jpg,crops,chroma,items,qa}
```


Если нужен детерминированный вспомогательный скрипт, сохрани его в `$WORK`; не добавляй вспомогательные файлы ни к этому навыку, ни в финальную папку результата.


## Неизменяемые правила качества


- До первой генерации или правки изображения прочитай и соблюдай встроенный навык `imagegen`.
- Генерируй ровно один предмет на каждый результат, кроме подтверждённой пары, например обуви или носков.
- Исключай человека, тело, кожу, волосы, манекен, вешалку, реквизит, другие слои одежды и сцену.
- Предпочитай пропуск выдумыванию. Не угадывай нечитаемый текст, скрытую конструкцию, брендинг, карманы, застёжки, фурнитуру или отделку.
- Переводи фрагмент в ожидание, если тип предмета или определяющую конструкцию нельзя восстановить без существенного вымысла.
- Объединяй дубли только тогда, когда исходные фотографии подтверждают, что это один физический предмет. Сходство сгенерированных изображений не является доказательством.
- Визуально проверяй исходные кропы и финальные контактные листы. Числовые проверки альфа-канала не могут подтвердить соответствие источнику.


## Рабочий процесс


### 1. Найди и нормализуй исходные фотографии


Сначала используй `rg --files`. Включай распространённые растровые форматы: JPEG, PNG, WebP, HEIC/HEIF, TIFF, BMP и AVIF. Исключай из поиска запрошенный путь результата и временную рабочую область.


Создай правильно ориентированные высококачественные рабочие JPEG-копии в `$WORK/source-jpg`:


- Примени ориентацию EXIF.
- Сохраняй исходные размеры в пикселях, кроме случаев нехватки памяти; никогда не увеличивай изображение.
- Только рабочую копию преобразуй в RGB JPEG с качеством 95 или выше.
- Разрешай одинаковые базовые имена с помощью короткого стабильного хеша относительного пути исходника.
- Записывай исходный путь, нормализованное имя файла, размеры и хеш источника в `$WORK/sources.json`.
- Используй Pillow, если библиотека декодирует формат; на macOS используй `sips`, а `ffmpeg` — как резервный вариант для HEIC/AVIF.


Создавай контактные листы исходников максимум по 12 изображений, подписывая их нормализованными именами файлов. Открой и проверь каждый лист. Не определяй гардероб только по именам файлов.


Для больших папок раздели инвентаризацию только для чтения между субагентами, выдав им непересекающиеся пакеты исходников. Один главный агент должен отвечать за глобальную идентичность предметов, решения о дублях, согласование генераций и финальный QA.


### 2. Инвентаризируй каждый намеренно надетый предмет


Включай верх, низ, верхнюю одежду, платья, обувь, чулочно-носочные изделия, купальники, ремни, галстуки и головные уборы. Исключай реквизит, не являющийся одеждой, если пользователь не запросил его отдельно.


Создай внутренний манифест следующей формы в `$WORK/manifest.json`:


```json
{
  "items": [
    {
      "slug": "navy-fair-isle-cardigan",
      "label": "Navy Fair Isle Cardigan",
      "category": "outerwear",
      "status": "generate",
      "confidence": "high",
      "description": "Длинный тёмно-синий кардиган на молнии с белой кокеткой Fair Isle и мелким точечным узором в нижней части.",
      "observed": {
        "color": "тёмно-синий и белый",
        "material": "трикотаж средней плотности",
        "silhouette": "длинный свободный прямой корпус",

### 3. Подготовь сфокусированные референсы для генерации


Для каждой записи `generate`:


1. Преобразуй нормализованную ограничивающую рамку в пиксели.
2. Добавь примерно 12% отступа с каждой стороны, ограничив его границами изображения.
3. Отклони кроп, если меньшая исходная сторона короче примерно 64 пикселей, кроме действительно узких предметов, например ремня или галстука.
4. Сохрани пропорции и помести кроп на нейтральный квадратный холст размером примерно 1200–1400 пикселей.
5. Сохрани основной кроп как `$WORK/crops/SLUG.jpg`, а дополнительный — как `SLUG-ref2.jpg`.


Создай подписанные контактные листы кропов и проверь их. Оставляй достаточно контекста, чтобы отличить целевой предмет от нижних слоёв, но делай цель доминирующей. Не объединяй референсы только потому, что одежда выглядит похожей.


### 4. Создай для каждого предмета один промт Imagegen, ограниченный свидетельствами


Используй следующую структуру, заменяя каждую скобку данными из источника и удаляя неприменимые фразы:


```text
Сценарий использования: удаление фона
Тип ресурса: прозрачная каталожная вырезка одежды для электронной коммерции, сначала сгенерированная на удаляемом хромакее
Входные изображения: референсные фотографии показывают один и тот же точный [ITEM] на человеке. Используй их только для определения и реконструкции этого предмета. Изображение 1 даёт [SILHOUETTE/CONSTRUCTION]. Изображение 2 даёт [DETAIL], если присутствует. Не смешивай детали визуально похожей одежды.
Основной запрос: реконструируй ТОЛЬКО полный пустой [ITEM NAME] как чистую каталожную фотографию товара для электронной коммерции в ракурсе [FRONT/ANGLE]. Соответствие предмету: сохрани подтверждённые источником [COLOR], [MATERIAL/TEXTURE], [SILHOUETTE], [NECKLINE/WAIST/OPENING], [SLEEVES/LEGS/SHAFTS], [FASTENING], [HEM/SOLE], [PATTERN] и [CLEAR MARKS]. [STATE UNKNOWNS AND WHAT TO OMIT.] Не выдумывай другие логотипы, надписи, ярлыки, карманы, швы, застёжки, фурнитуру, цвета или украшения.
Композиция: холст [SQUARE/PORTRAIT/LANDSCAPE], по центру [VIEW], полный предмет целиком внутри кадра с большим равномерным отступом от каждого внешнего края; без обрезки и усечения.


Фон: идеально плоский, абсолютно равномерный однотонный [CHROMA KEY] от края до края. Фон должен состоять ровно из одного цвета без тени, градиента, текстуры, виньетки, пола, горизонта, отражения или перепада освещения.
Освещение: нейтральное рассеянное премиальное освещение для электронной коммерции, действующее только на предмет; без отбрасываемой или контактной тени, отражения, реквизита, водяного знака, подписи или рамки.


Критически важно: нигде в предмете не используй [CHROMA KEY]; сохрани чёткий отделяемый внешний силуэт; выведи только один [ITEM OR MATCHED PAIR].
```


Используй формулировки, прямо основанные на свидетельствах:


- `Сохрани четыре маленькие белые пуговицы, видимые в вертикальном ряду.`
- `Розовая ткань — отдельный нижний слой, и она не должна появляться.`
- `Тёмные формы внизу — тени от листьев, а не принт.`
- `Метка источника не читается; пропусти текст, а не выдумывай его.`
- `Конструкция горловины не определена; используй простейшую конструкцию, соответствующую видимому отверстию.`


Избегай расплывчатых запросов вроде `сделай это стильным`, `улучши дизайн` или `естественно заверши`; они провоцируют выдумывание деталей.


Выбери хромакей:


- По умолчанию используй чистый `#00ff00`.
- Для зелёной одежды используй `#ff00ff`, если пурпурный или розовый цвет не является заметной частью изделия.
- В остальных случаях выбери максимально удалённый чистый насыщенный RGB-цвет и запиши его как `chroma_key`.
- Требуй один и тот же сплошной цвет во всех пикселях границы.


Выбери кадрирование по категории:


- Верх и верхняя одежда: вид спереди с отверстием горловины, полными рукавами, манжетами и низом.
- Брюки и колготки: портретный вид с поясом, полными штанинами и целыми краями или закрытыми стопами.
- Юбки и платья: вид спереди с поясом или горловиной, полной длиной и целым нижним краем.
- Обувь: только подтверждённая пара; используй слегка приподнятый передний ракурс в три четверти, когда важны отверстия и подошвы.
- Ремни и галстуки: располагай длинную ось по горизонтальному или вертикальному холсту и сохраняй оба конца целиком.
- Купальники: полностью показывай каждую бретель и конец завязки.


### 5. Сгенерируй и согласуй результаты


Используй встроенный Imagegen с основным кропом и только действительно дополняющим вторым кропом. Сохрани возвращённое изображение на хромакее в `$WORK/chroma/SLUG.png`, а точный промт — во временных записях.


Если предметов больше восьми, раздели непересекающиеся пакеты slug между субагентами. Для каждого slug разрешай только одну активную генерацию. Требуй, чтобы каждый исполнитель вернул slug, промт, пути к референсам, путь к chroma-файлу и краткий визуальный обзор. Сверь все результаты с манифестом и продолжай только отсутствующие или неудачные slug.


Перед принятием сравни каждый результат на хромакее с исходником. Одной правдоподобности недостаточно.


### 6. Удали хромакей-фон


При наличии предпочитай проверенный вспомогательный скрипт встроенного навыка Imagegen:


```bash
python3 "${CODEX_HOME:-$HOME/.codex}/skills/.system/imagegen/scripts/remove_chroma_key.py" \
  --input "$WORK/chroma/SLUG.png" \
  --out "$WORK/items/SLUG.png" \
  --auto-key border \
  --soft-matte \
  --transparent-threshold 12 \
  --opaque-threshold 220 \
  --despill \
  --force
```


Если скрипт недоступен, временно реализуй аналогичную операцию с Pillow:


1. Возьми медианное RGB-значение из тонкой полосы вдоль всех четырёх границ.
2. Для каждого пикселя измерь максимальное поканальное расстояние от выбранного ключа.
3. Сделай расстояние `<=12` полностью прозрачным, а расстояние `>=220` — полностью непрозрачным.
4. Между этими порогами используй плавную smoothstep-кривую альфа-канала и умножь её на исходную альфу.
5. Для частично прозрачных пикселей ограничь доминирующие каналы ключевого цвета значением сильнейшего неключевого канала, чтобы убрать цветовой ореол.
6. Установи полностью прозрачные пиксели в `(0, 0, 0, 0)` и сохрани RGBA PNG.


Используй выбор ключа по границе только тогда, когда сгенерированный фон визуально равномерен. Если удаление повреждает цвета одежды, перегенерируй изображение с более удалённым ключом, а не применяй разрушительную маску.


### 7. Выполни технический и визуальный QA


Для каждого PNG проверь с помощью Pillow или аналогичного декодера:


- формат PNG и режим RGBA;
- альфа-канал содержит и прозрачные, и видимые пиксели;
- все четыре угла прозрачны;
- внешняя граница преимущественно прозрачна;
- непрозрачное содержимое не пусто и не занимает почти весь холст;
- ограничивающая рамка альфа-канала оставляет видимый отступ, а крайние части предмета не обрезаны;
- на частично прозрачных краях нет очевидных пикселей цвета хромакея;
- каждому slug со статусом `generate` соответствует ровно один результат и нет необъяснимых дополнительных файлов.


Создавай контактные листы вырезок на шахматном фоне максимум по 12 предметов в `$WORK/qa`. Проверь каждый лист, затем отдельно сравни чувствительные предметы с исходными кропами.


Применяй следующую визуальную шкалу:


1. Подтверди идентичность цели и категорию.
2. Сравни пропорции, силуэт, цвет и характер материала.
3. Сравни горловину, посадку, пояс, отверстие, длину рукава или штанины, низ и форму подошвы.
4. Сравни застёжки, карманы, отделку, размещение узора и чётко читаемые метки.
5. Подтверди полноту топологии: каждый рукав, манжета, бретель, завязка, край, носок обуви, пятка, голенище или закрытая стопа.
6. Подтверди отсутствие частей тела, нижних слоёв, соседней одежды, реквизита, тени и фона.
7. Отклоняй неподтверждённую конструкцию и выдуманный текст.


Классифицируй ошибки так:


- Критическая: неверный предмет, осталось тело, в предмет вросла другая одежда, значительная обрезка, непрозрачный фон или разрушительная маска. Перегенерируй.
- Значительная: выдуманный капюшон, воротник, карман или застёжка, неверный силуэт или цвет, поддельный логотип/текст, пропущенный определяющий узор или незавершённые концы. Исправь или перегенерируй.
- Незначительная: слабый ореол по краю, небольшое смещение центра или малозаметное отклонение текстуры. Исправь, если это видно в каталожном размере.


При исправлении приложи текущий результат и самый сильный исходный кроп, затем используй:


```text
Исправь приложенную каталожную вырезку с помощью исходного кропа. Сохрани удачный силуэт, цвет и композицию процесса с хромакеем. Удали неподтверждённый [FAILURE]. Восстанови подтверждённый источником [DETAIL]. Не добавляй [COMMON HALLUCINATION]. Верни исправленный предмет на том же равномерном фоне [CHROMA KEY] без тени.
```


Если предмет дважды не проходит проверку, перепиши промт вокруг наблюдаемой ошибки, а не повторяй его без изменений.


### 8. Выполни консервативную дедупликацию


Используй перцептивные хеши или сходство силуэта/цвета только для ранжирования пар перед проверкой. Никогда не удаляй автоматически по сходству сгенерированных изображений.


Подтверждай идентичность по исходным фотографиям: совпадающей отличительной конструкции, размещению узора, потёртостям, фурнитуре или логотипам; совместимым цвету и материалу; отсутствию противоречащих деталей. Повторяющийся контекст образа или последовательность соседних фотографий являются вспомогательным, но не единственным доказательством.


Не объединяй обычные чёрные юбки, однотонные топы, джинсы или обувь только потому, что Imagegen стандартизировал их позы. Если исходные свидетельства неоднозначны, сохрани оба предмета. Оставляй один канонический slug только для дублей, подтверждённых источником.


### 9. Выдай только готовые PNG


После прохождения проверки всеми принятыми предметами:


1. Убедись, что запрошенная папка результата всё ещё не существует.
2. Создай эту единственную папку внутри текущей рабочей директории.
3. Скопируй в неё только принятые канонические `.png` из `$WORK/items`.
4. Повторно открой каждый скопированный файл и подтверди RGBA и прозрачность.
5. Убедись, что папка не содержит файлов, отличных от PNG, псевдонимов дублей или вспомогательных материалов.
6. Удали `$WORK` только после успешной финальной проверки.


Верни абсолютный путь к папке результата и количество PNG. Покажи пользователю в чате до 12 изображений и сообщи, что остальные доступны в директории. Кратко упомяни фрагменты, которые невозможно было восстановить.
````
