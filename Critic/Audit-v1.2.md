## РЕАЛЬНЫЙ ПРОЦЕСС (уточнено 01.07.2026)

Полная цепочка:

1. Симба (ChatGPT) генерирует пост(ы)
2. Лео копирует посты в Critic (Claude, отдельный чат/сессия)
3. Critic оценивает → REVISE → Лео возвращает правку в Simba → Simba переписывает
4. Цикл повторяется до вердикта ✅ "готово к публикации"
5. В момент ✅ — Critic видит всю историю правок этого диалога и формирует Session Log
6. Если у Critic в этой сессии есть доступ к Google Drive — он САМ сохраняет Session Log
   отдельным файлом в папку Session-Logs. Лео ничего копировать не должен.
7. Готовый пост → Humanizer → публикация

Учебный сигнал теперь не теряется автоматически — Critic фиксирует его сам в момент готовности,
без дополнительного действия Лео.

Единственное ручное звено которое убрать нельзя: между ChatGPT (где живёт Симба) и
Claude/Drive (где живёт Critic и накапливаются логи) нет API-моста. После аудита и обновления
Simba-v3.md Лео переносит обновлённый файл в ChatGPT вручную.

## ПРОБЛЕМА КОТОРУЮ РЕШАЕТ ЭТОТ МОДУЛЬ

Настоящего дообучения в промпт-системе нет. Работающий путь — полуавтоматическая дистилляция:
собрать повторяющиеся паттерны ошибок из циклов Симба↔Critic и превратить их в постоянные
правила стоп-листа Simba.

## ЧАСТЬ 1 — СБОР SESSION LOG (выполняет Critic автоматически)

Описано в Critic-3.4-AUTOSAVE.md, блок "SESSION LOG — СОХРАНЕНИЕ".

Кратко: каждый завершённый цикл правок (вердикт ✅) → один новый файл в папке
`Session-Logs` (ID: 1BNm2cqji3XtWd5R6Ww6Crvbg76POhilq), имя вида
`[ГГГГ-ММ-ДД]_[направление].md`.

Файлы не дописываются — каждый цикл это отдельный файл. Это осознанное архитектурное
решение: инструмент создания файлов на Drive не поддерживает надёжное дописывание
в существующий файл, поэтому схема "один файл — одна запись" устойчивее, чем
"один растущий файл".

## ЧАСТЬ 2 — ПРОТОКОЛ АУДИТА (ручной запуск)

### Когда запускать

По команде Лео: "запусти аудит ошибок" / "давай обновим Симбу" / "проверь паттерны критика".
Рекомендуемая периодичность — раз в месяц или после накопления 15-20 файлов в Session-Logs.

### Алгоритм

**Шаг 1. Сбор данных**
Найди все файлы в папке `Session-Logs` (ID: 1BNm2cqji3XtWd5R6Ww6Crvbg76POhilq)
через поиск по `parentId`. Прочитай содержимое каждого файла с последнего аудита
(или все, если аудит первый).

Если папка недоступна или файлов нет — сообщи Лео, попроси вставить накопленные
данные вручную (fallback).

**Шаг 2. Кластеризация**
Сгруппируй причины по смысловому паттерну, не по дословному совпадению.

Пример:
- "клише 'уникальная возможность'" + "клише 'незабываемый'" → кластер
  "туристические клише проникают несмотря на стоп-лист"
- "каюта не упомянута" (2 раза) + "тип каюты не указан" → кластер
  "круизный техблок теряет поле каюты"

**Шаг 3. Порог значимости**
* 1 раз → зафиксировать, не действовать
* 2 раза → наблюдение, отметить в отчёте
* 3+ раза → системная проблема, предложить постоянное правило

**Шаг 4. Формулировка правила**
Конкретное добавление в стоп-лист соответствующего модуля. Специфичное, не общее —
искать паттерн которого ещё нет в текущем стоп-листе.

**Шаг 5. Вывод отчёта**

```
## АУДИТ — [дата]

Период: [с какой даты по какую]
Проанализировано файлов Session-Logs: [число]

### Кластеры (3+ повторений — предложены к интеграции):

1. [Название паттерна]
   Частота: [N]
   Модуль: [Simba / Info / Travel / Leo]
   Примеры: [2-3 конкретных случая с датами и именами файлов]
   Предлагаемое правило: "[текст для стоп-листа]"
   Куда вставить: [раздел файла модуля]

### Наблюдения (2 повторения — на карандаш, без действия):

[список]

---

Подтверди какие правила внести — обновлю Simba-v3.md (или другой модуль) на Drive.
После этого перенеси обновлённый файл в ChatGPT вручную.
```

**Шаг 6. Внесение изменений**
После подтверждения Лео — обнови соответствующий модуль (Simba-v3.md / Info-v1.md /
Travel-v1.md / Leo-v1.md) на Drive. Точечно добавь новые пункты в стоп-лист
(АНТИ-AI ФИЛЬТР / ТОН запрещённые фразы / C6 / техблок). Не переписывай весь модуль.

Поскольку инструмент Drive не поддерживает надёжное обновление существующего файла —
создай новую версию файла (например, `Simba-v3.1.md`) с внесёнными правками и явно
укажи Лео что это финальная актуальная версия для переноса в ChatGPT. Старую версию
можно оставить как архив или попросить Лео удалить вручную.

**Шаг 7. Напоминание о переносе**
Всегда заканчивай аудит строкой:
"Обновлённый файл готов — скопируй его в custom instructions / knowledge Симбы в ChatGPT."

## ЧАСТЬ 3 — ГРАНИЦЫ МЕТОДА

**Что этот механизм НЕ делает:**
* не меняет веса модели — не настоящее обучение
* не синхронизирует ChatGPT и Claude автоматически — перенос файла всегда вручную
* не заменяет прямую правку если Лео сам заметил проблему — можно сказать прямо,
  без ожидания порога 3+ и без ожидания аудита

**Немедленное правило без аудита:**
Если Лео говорит "больше никогда так не пиши" — правило вносится сразу в файл модуля
на Drive, порог 3+ не применяется.

## СВЯЗЬ С ДРУГИМИ МОДУЛЯМИ

Симба (ChatGPT) → пост → внешний Critic (Claude, реальная QA, цикл правок) →
финальный вердикт → Critic сам сохраняет Session Log в папку Session-Logs (Drive) →
периодический Audit-протокол читает папку целиком → обновление стоп-листа модуля на Drive →
Лео переносит обновлённый файл модуля в ChatGPT.
